## 二、课程目标

### 1. 知识目标

- 掌握 GPIO、ADC、PWM、UART、I2C、SPI、单总线 七类外设的工作原理与官方驱动用法。
- 掌握 FreeRTOS 的任务、队列、信号量、事件组与中断协作机制。
- 掌握嵌入式网络编程：WiFi（AP/STA）、UDP/TCP Socket、HTTP 服务器。
- 掌握典型传感器的数据手册阅读方法与驱动移植流程。
- 理解姿态解算、气压测高、光流测位移、图像采集的基本原理。

### 2. 能力目标

- 能够阅读原理图与数据手册，独立完成传感器驱动的配置与调试。
- 能够使用官方 API 设计多任务系统，正确处理并发、同步与共享资源。
- 能够使用逻辑分析仪、示波器与日志系统定位软硬件故障。
- 能够完成"数据采集 → 处理 → 通信 → 执行"的完整功能闭环。

### 3. 素养目标

- 形成"先验证硬件、再审查代码"的工程排查习惯。
- 建立规范意识：命名清晰、注释到位、模块解耦、版本可追溯。
- 建立安全意识：电平匹配、电源隔离、失控保护、地面测试优先。

## 五、教学方式与实施要求

### 1. 统一教学节奏

- **原理导入（15 分钟）**：从物理现象或协议时序切入，明确本节要解决的问题。
- **代码精讲（25 分钟）**：现场打开官方示例，逐段说明配置结构体与 API 的作用。
- **动手实操（35 分钟）**：学生按步骤完成实验，教师巡回指导。
- **联调排故（15 分钟）**：引入一个典型故障现象（接线错误、配置遗漏、时序冲突），组织集体排查。
- **总结与思考（10 分钟）**：回答思考题，布置拓展任务。

### 2. 代码阅读方法

- 先读头文件，明确函数的输入与输出。
- 再读配置结构体，理解该外设有哪些可调参数。
- 最后读调用流程，建立"配置 → 启停 → 读写"的固定印象。

### 3. 工程习惯要求

- 每个外设的初始化代码集中写在一个函数中，主流程只负责调度。
- 所有返回值都要判断，失败时打印日志并给出明确的故障描述。
- 所有日志使用 `ESP_LOGI(TAG, "...")` 形式，`TAG` 用模块名，便于过滤。
- 修改代码遵循"一次只改一个变量"的原则，便于定位问题。

## 六、基础准备

### 6.1 开发工具链与工程结构

#### 1. 三种开发方式的取舍

| 方式 | 特点 | 适用场合 |
| --- | --- | --- |
| **ESP-IDF** | 乐鑫官方原生框架，C 语言，组件化，原生 FreeRTOS 支持 | 本课程主用，外设与系统能力教学 |
| **Arduino** | 库生态丰富，`setup()/loop()` 结构简单 | 快速验证单个传感器 |
| **PlatformIO** | VS Code 插件式构建系统，可在同一工程中切换框架 | 需要同时管理多平台工程时 |

本课程统一使用 ESP-IDF，避免框架混用带来的工程结构问题。

#### 2. ESP-IDF 的分层结构

从上到下依次为：

1. **应用层**（`main/`）：课程代码与业务逻辑；
2. **组件层**（`components/`）：功能独立的驱动模块，如 `my_driver`；
3. **驱动层**（`driver/`、`esp_driver_*`）：乐鑫提供的官方外设驱动；
4. **硬件层**：芯片外设寄存器与引脚。

调用关系是单向的：应用层调用组件层，组件层调用驱动层，驱动层操作硬件寄存器。

#### 3. 启动流程

ESP32-S3 上电后并不是直接执行 `app_main()`，中间要经过几道"交接"：

| 顺序 | 阶段 | 做什么 |
| --- | --- | --- |
| 1 | 一级引导程序（ROM Boot） | 芯片内部固化的一小段程序，决定从哪里启动 |
| 2 | 二级引导程序（bootloader） | 读出分区表，找到应用程序在 Flash 里的位置 |
| 3 | 加载应用程序 | 把程序从 Flash 搬到内存，准备运行 |
| 4 | 启动 FreeRTOS | 初始化系统，创建"主任务" |
| 5 | 主任务调用 `app_main()` | 从这里开始执行我们写的代码 |
| 6 | FreeRTOS 开始调度 | `app_main` 里创建的任务开始轮流运行 |

**知道这个顺序有什么用**

- 程序**上电就重启**时，问题往往出在前 3 步（供电不稳、Flash 内容损坏、分区表不对），而不在代码逻辑里；
- `app_main()` 本身也是一个任务（主任务），**它执行完不代表程序结束** —— 只要还有别的任务在跑，系统就继续运行；
- 串口最先打印的那几行通常是引导程序输出的，可以据此判断芯片究竟走到了哪一步。

#### 4. 分区表

分区表（`partitions.csv`）描述 Flash 的划分方式，常见分区如下：

| 分区 | 用途 |
| --- | --- |
| `nvs` | 键值对存储，保存 WiFi 账号、校准参数 |
| `phy_init` | 射频校准数据 |
| `factory` | 出厂应用程序 |
| `ota_0` / `ota_1` | OTA 升级用的双备份应用分区 |

芯片不会自己知道哪块 Flash 存程序、哪块存数据，全靠这张表告诉它。

**怎么查看自己工程的分区表**

- 工程里有 `partitions.csv` 时，打开它就是分区方案；
- 没有自定义时，使用的是 IDF 的默认分区表；
- 编译后用 `idf.py partition-table` 可以打印最终生效的分区表。

**实践中最常见的两个问题**

1. **程序太大放不下** —— 报错 `app partition is too small`，说明 `factory` 分区容量不够，需要把应用分区调大；
2. **NVS 写满** —— 报 `ESP_ERR_NVS_NOT_ENOUGH_SPACE`，说明 `nvs` 分区太小，或旧数据没清理。

**注意**：改过分区表之后必须**完整重新烧录**（包括分区表本身），只烧应用程序不会生效。

#### 5. 工程目录约定

```
工程目录/
├── CMakeLists.txt          顶层构建脚本
├── sdkconfig               配置结果（menuconfig 生成）
├── partitions.csv          分区表（可选）
├── components/             自定义组件
│   └── my_driver/
│       ├── CMakeLists.txt
│       ├── my_driver.c
│       └── include/my_driver.h
└── main/
    ├── CMakeLists.txt
    └── main.c              app_main 入口
```

组件注册写法：

```cmake
idf_component_register(
    SRCS "my_driver.c"
    INCLUDE_DIRS "include"
    REQUIRES driver esp_driver_gpio
)
```

- `SRCS` 列出源文件，`INCLUDE_DIRS` 声明对外头文件目录。
- `REQUIRES` 声明依赖的官方组件；声明后该项目才能 `#include` 对应头文件。

#### 6. 构建与烧录

```
idf.py build                     编译
idf.py -p COM3 flash             烧录
idf.py -p COM3 monitor           查看日志（Ctrl + ] 退出）
idf.py menuconfig                图形化配置
```

#### 7. 程序入口

```c
#include "esp_log.h"

static const char *TAG = "app";

void app_main(void)
{
    ESP_LOGI(TAG, "system started");
}
```

### 6.2 调试方法与工具

调试能力是嵌入式开发的核心能力之一。本节给出从"看现象"到"看回溯"的完整手段。

#### 1. 用 LED 看现象

最直接的判断方式：**灯在闪，说明程序还在跑；灯停了，说明程序卡住了。**

在可疑代码前后各插入一次快速闪烁，即可把故障范围缩小到两行之间：

```c
#include "driver/gpio.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

#define DEBUG_LED   GPIO_NUM_2

static void mark(void)
{
    for (int i = 0; i < 3; i++)
    {
        gpio_set_level(DEBUG_LED, 1);
        vTaskDelay(pdMS_TO_TICKS(100));
        gpio_set_level(DEBUG_LED, 0);
        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

void app_main(void)
{
    gpio_set_direction(DEBUG_LED, GPIO_MODE_OUTPUT);

    while (1)
    {
        mark();                                   /* 标记点：程序执行到这里了 */
        vTaskDelay(pdMS_TO_TICKS(2000));
    }
}
```

#### 2. 分级日志

| 接口 | 级别 | 用途 |
| --- | --- | --- |
| `ESP_LOGE(TAG, ...)` | 错误 | 初始化失败、通信异常 |
| `ESP_LOGW(TAG, ...)` | 警告 | 可恢复的异常，如重连 |
| `ESP_LOGI(TAG, ...)` | 信息 | 关键流程节点、测量结果 |
| `ESP_LOGD(TAG, ...)` | 调试 | 开发阶段的细节输出 |

使用规范：

- `TAG` 用模块名，便于按模块过滤日志；
- 高频循环中不要打印日志，日志本身会拖慢实时任务；
- 整数用 `%d`、字符串用 `%s`、浮点用 `%.1f`，格式符写错会打印出乱码。

#### 3. 崩溃回溯定位

程序异常重启时，`idf.py monitor` 会打印被重定向后的调用栈信息（Backtrace）。把其中的地址交给 `addr2line`，即可定位到具体函数与行号：

```
idf.py monitor
xtensa-esp32s3-elf-addr2line -pfiaC -e build/工程名.elf 0x42012345
```

常见崩溃原因：空指针访问、数组越界、任务栈溢出、在中断中调用了阻塞式接口。

#### 4. eFuse（芯片内部熔丝）

eFuse 是芯片内部**一次性可编程**的存储区，写入后不可撤销，常用于保存 MAC 地址、Flash 加密密钥、安全启动配置等。

- **查看**（安全操作）：`espefuse.py -p COM3 summary`
- **烧写**（危险操作）：命令中含 `burn` 字样的都会写入熔丝。

**规范要求**：课程阶段只允许执行 `summary` 查看，任何 `burn` 操作必须先向教师确认。误写熔丝可能导致芯片无法再下载程序。

#### 5. 常用调试工具

| 工具 | 能解决什么 | 典型用法 |
| --- | --- | --- |
| 万用表 | 供电是否正常、电平是否正确、通断是否连通 | 量 VCC 与 GND 之间的电压、量引脚电平 |
| 逻辑分析仪 | 通信时序是否正确（I2C / SPI / UART / 单总线） | 抓一帧波形，对照数据手册核对 |
| 示波器 | PWM 占空比、波形质量、电源纹波 | 测 PWM 高电平持续时间 |
| 串口监视器 | 程序执行到哪一步、变量值是多少 | `idf.py monitor` |
| 网络调试助手 | UDP / TCP 数据收发 | 接收设备上报、下发控制指令 |
| `nRF Connect` | BLE 服务与特征值调试 | 手机端读写特征值 |

#### 6. 通用排查顺序

1. **供电与接线**：电源是否稳定、是否共地、引脚是否接对、电平是否匹配；
2. **总线是否存活**：I2C 扫描地址、UART 自收发、SPI 抓波形、GPIO 量电平；
3. **驱动是否初始化成功**：检查返回值与日志，读取身份寄存器确认器件在线；
4. **数据是否正确**：单位、字节序、符号、量程、校准；
5. **系统是否稳定**：任务栈、优先级、临界区、内存、看门狗。

**原则**：一次只改一个变量；能用硬件验证的，不要凭猜测。

### 6.3 基础元器件知识

#### 1. 二极管

- **特性**：只允许电流单向通过。硅二极管正向压降约 0.7V，肖特基二极管约 0.3V。
- **作用一：续流**。继电器、电机、水泵等**感性负载**在关断瞬间会产生反向电动势，必须在线圈两端**反向并联**一只二极管（阴极接电源正极）将其吸收，否则会击穿驱动管或芯片引脚。
- **作用二：防反接**。串在电源输入端，防止电源正负极接反。
- **极性识别**：管体上有色环的一端为阴极（负极）。

#### 2. 三极管

**三个电极**

| 电极 | 英文 | 符号 | 作用 |
| --- | --- | --- | --- |
| 基极 | Base | **B** | 控制极，靠电流控制通断 |
| 集电极 | Collector | **C** | NPN 的电流流入端 |
| 发射极 | Emitter | **E** | 电流流出端，符号上的箭头由此指出 |

**两种类型的触发条件**

| 类型 | 符号特征 | 导通条件 | 关断条件 | 电流方向 |
| --- | --- | --- | --- | --- |
| **NPN** | 箭头**朝外**（E 指向外） | `Vbe ≥ 0.7V`，即基极比发射极**高** 0.7V | `Vbe < 0.5V` | C → E |
| **PNP** | 箭头**朝内**（指向 B） | `Veb ≥ 0.7V`，即基极比发射极**低** 0.7V | `Veb < 0.5V` | E → C |

**记忆口诀**：**NPN 基极抬高 0.7V 就通；PNP 基极拉低 0.7V 就通。**

**用在 GPIO 上要注意的逻辑关系**：

| 类型 | 接线位置 | GPIO 写 1 | GPIO 写 0 |
| --- | --- | --- | --- |
| NPN | 低边驱动（负载在上，管在下到地） | 导通（开） | 关断 |
| PNP | 高边驱动（管在上接电源，负载在下） | 关断 | 导通（开） |

也就是说：**NPN 的逻辑是"正"的，PNP 的逻辑是"反"的**。3.3V 的 GPIO 驱动 NPN 余量充足（阈值仅 0.7V），驱动 PNP 时要特别注意引脚电位关系。

**三个工作区**

| 工作区 | 条件 | 等效状态 | 用途 |
| --- | --- | --- | --- |
| 截止区 | `Vbe < 0.5V` | 断开 | 开关的"关" |
| 放大区 | `Vbe ≥ 0.7V`，且 `Vce` 较大 | 受控电流源 | 模拟信号放大 |
| 饱和区 | `Vbe ≥ 0.7V`，且 `Vce ≤ 0.3V` | 闭合 | 开关的"开" |

嵌入式开发只使用**截止**与**饱和**两个状态，让三极管工作在"开关"而非"放大"状态。

**常见型号与触发条件**

| 型号 | 类型 | 最大集电极电流 | 放大倍数 hFE | 触发条件 | 常见用途 |
| --- | --- | --- | --- | --- | --- |
| S8050 | NPN | 700mA | 85 ~ 300 | `Vbe ≈ 0.7V` | 驱动继电器、蜂鸣器 |
| S8550 | PNP | 700mA | 85 ~ 300 | `Veb ≈ 0.7V` | 高边驱动、与 S8050 配对 |
| S9013 | NPN | 500mA | 100 ~ 600 | `Vbe ≈ 0.7V` | 通用小功率开关 |
| 2N3904 | NPN | 200mA | 100 ~ 300 | `Vbe ≈ 0.7V` | 小信号与开关 |
| 2N3906 | PNP | 200mA | 100 ~ 300 | `Veb ≈ 0.7V` | 与 2N3904 配对 |
| TIP122 | NPN 达林顿 | 5A | ≥ 1000 | **`Vbe ≈ 1.2 ~ 2.5V`** | 大电流负载 |

**注意 TIP122 这类达林顿管**：内部相当于两级三极管串联，基极阈值是**普通三极管的两倍左右**（约 1.4V），而且随电流增大还会升高。3.3V 驱动时余量明显变小，实际工程中更常用 **ULN2003**（内部集成 7 路达林顿管与续流二极管）来驱动继电器与步进电机。

**基极电阻怎么算**

```
Ib = (Vgpio − Vbe) / Rb          基极电流
Ib ≥ Ic / hFE                    保证进入饱和区
```

**计算示例**：3.3V GPIO 驱动 100mA 的继电器，选用 S8050（hFE 按 100 计算）：

1. 所需最小基极电流 `Ib = 100mA / 100 = 1mA`；
2. 留 3 倍余量保证深度饱和，取 `Ib = 3mA`；
3. `Rb = (3.3 − 0.7) / 0.003 ≈ 866Ω`，取标称值 **680Ω 或 1kΩ**。

余量必须留足：如果按临界值设计，三极管会停留在放大区，`Vce` 偏高，管子上会消耗大量功率而发热。

#### 3. MOS 管

**三个电极**

| 电极 | 英文 | 符号 | 作用 |
| --- | --- | --- | --- |
| 栅极 | Gate | **G** | 控制极，靠**电压**控制通断，几乎不耗电流 |
| 漏极 | Drain | **D** | 电流流入或流出端 |
| 源极 | Source | **S** | 电流流出或流入端，箭头方向由此指出 |

**与三极管的根本区别**：

| 对比项 | 三极管 | MOS 管 |
| --- | --- | --- |
| 控制方式 | **电流**控制（基极需持续注入电流） | **电压**控制（栅极几乎不耗电） |
| 驱动功耗 | 持续消耗基极电流 | 静态几乎为零 |
| 导通电阻 | 饱和压降约 0.3V，压降固定 | `Rds(on)` 很小（毫欧级） |
| 适合场合 | 中小电流开关 | 大电流、长时间导通 |

**四种类型**

| 类型 | 符号箭头 | 触发条件 | 使用情况 |
| --- | --- | --- | --- |
| **N 沟道增强型** | 箭头朝内 | `Vgs > Vgs(th)`，栅极比源极**高** | **最常用**，低边驱动 |
| P 沟道增强型 | 箭头朝外 | `Vgs < −Vgs(th)`，栅极比源极**低** | 高边驱动、电源开关 |
| N 沟道耗尽型 | — | 默认导通，需负压关断 | 极少使用 |
| P 沟道耗尽型 | — | 默认导通，需正压关断 | 极少使用 |

**结论**：实际工程只用**增强型**（N 沟道与 P 沟道两种）。耗尽型出厂即导通，与"给信号才通"的直觉相反，课程实验不会用到。

**N 沟道与 P 沟道的驱动接法与逻辑**

| 项目 | N 沟道 | P 沟道 |
| --- | --- | --- |
| 导通条件 | `Vgs > Vgs(th)`（栅极高于源极） | `Vgs < −Vgs(th)`（栅极低于源极） |
| 常用位置 | **低边驱动**：负载接电源，MOS 在下方到地 | **高边驱动**：MOS 在上方接电源，负载在下方 |
| 源极接法 | 源极接 **GND** | 源极接 **VCC** |
| GPIO 写 1 | 导通（开） | 关断 |
| GPIO 写 0 | 关断 | 导通（开） |
| 栅极电阻 | 下拉到 GND（约 10kΩ） | 上拉到 VCC（约 10kΩ） |

**不同型号的触发条件（选型的关键）**

| 型号 | 类型 | `Vgs(th)` 范围 | 3.3V 能否完全导通 | 最大电流 | 典型用途 |
| --- | --- | --- | --- | --- | --- |
| **AO3400** | N 沟道 逻辑电平 | 0.65 ~ 1.45V | **能**（2.5V 时 `Rds(on) ≈ 48mΩ`） | 5.7A | 首选，驱动水泵 / 雾化 / 电机 |
| SI2302 | N 沟道 逻辑电平 | 0.65 ~ 1.5V | 能 | 2.5A | 小功率负载 |
| 2N7000 | N 沟道 小信号 | 0.8 ~ 3V | 勉强（电流仅百毫安级） | 200mA | 电平转换、小信号 |
| IRLZ44N | N 沟道 逻辑电平 | 1 ~ 2V | 能，但 3.3V 下导通电阻偏大 | 47A | 大电流，建议 5V 驱动 |
| **IRF540N** | N 沟道 **标准型** | 2 ~ 4V | **不能**（需 10V 才充分导通） | 33A | 必须配专用驱动电路 |
| AO3401 | P 沟道 逻辑电平 | −0.9 ~ −1.3V | 能（高边驱动） | 4A | 电源开关 |

**选型三步法**：

1. **看 `Vgs(th)` 上限**：3.3V 驱动必须选**逻辑电平型**，且 `Vgs(th)` 上限最好不超过 1.5V（留出一倍以上余量）；
2. **看手册中 `Rds(on)` 的测试条件**：必须找 `Vgs = 2.5V` 或 `4.5V` 那一栏。如果手册只给了 `Vgs = 10V` 的数据，说明它在 3.3V 下无法充分导通；
3. **核算功耗**：`P = I² × Rds(on)`，再乘散热条件判断是否会过热。

**课堂反例 —— IRF540N**：很多同学从元件盒里翻出一只 IRF540N，用 3.3V GPIO 直接驱动电机，结果"半开"、管子发烫、电机还带不动。原因就是它的 `Vgs(th)` 上限达 4V，而手册标注的 `Rds(on) = 44mΩ` 是在 `Vgs = 10V` 条件下测得的。

**栅极驱动的三个细节**

- **必须接下拉电阻**（N 沟道，约 10kΩ 到 GND）：栅极悬空时受干扰会误导通，这是 MOS 最常见的故障；
- **栅极串一只 10Ω ~ 100Ω 电阻**：抑制开关瞬间的振荡，减小栅极电流冲击；
- **感性负载仍要并续流二极管**：MOS 内部的体二极管只能吸收部分能量，不能替代续流二极管。

#### 4. 电阻

- **作用**：限流、分压、上拉、下拉、采样。
- **欧姆定律**：`U = I × R`；功率 `P = U × I = U² / R`。
- **典型应用**：
  - LED 限流：3.3V 供电、LED 压降 2V、目标电流 10mA，则 `R = (3.3 - 2) / 0.01 = 130Ω`，实际取标称值 150Ω 或 220Ω。
  - 分压采样：光敏电阻与固定电阻串联，中点电压反映光照强度。
  - I2C 上拉：4.7kΩ 拉到 3.3V。
- **功率校核**：`P = U² / R`，若计算值接近电阻额定功率（常用 1/4W），需换更大功率的电阻。

#### 5. 电容

- **作用**：储能、滤波、去耦、隔直通交、上电延时。
- **去耦电容**：每个电源引脚旁边放一只 **0.1μF** 陶瓷电容到地，滤除高频噪声。
- **储能电容**：电源输入端放一只 **10μF ~ 100μF** 电解电容，应对负载瞬时电流需求。
- **按键消抖**：按键两端并联 0.1μF 电容，配合软件延时，抑制机械抖动的误触发。
- **注意**：电解电容有极性，长脚为正；陶瓷电容无极性。

#### 6. 电感

- **作用**：储存磁场能量，与电容配合构成 LC 滤波，是开关电源（DC-DC）的核心元件。
- **单位与标识**：单位是亨利（H），常用 μH / mH，元件上用数字或色环标注。
- **两个必须记住的特性**：
  1. **电流不能突变** —— 电感会阻止流过它的电流瞬间变化；
  2. **断电产生反向电动势** —— 电流突然断开时，电感两端会产生很高的反向电压。
- **本课程中的实际影响**：继电器、电机、水泵这类"线圈"本质上就是电感。所以关断瞬间必须并**续流二极管**，把反向电压泄放掉，否则会打穿驱动管或芯片引脚。
- **初学阶段的要求**：知道它是什么、记住"感性负载要加续流二极管"就够了，不需要自己设计 LC 滤波电路。

#### 7. 元器件速查表

| 元器件 | 一句话作用 | 本课程中最常见的用例 |
| --- | --- | --- |
| 二极管 | 电流单向导通 | 电机、继电器的续流二极管 |
| 三极管 | 小电流控制大电流 | 驱动蜂鸣器、继电器 |
| MOS 管 | 大电流电子开关 | 驱动水泵、雾化片、电机 |
| 电阻 | 限流、分压、上下拉 | LED 限流、I2C 上拉、按键上下拉 |
| 电容 | 储能与滤波 | 电源去耦、按键消抖 |
| 电感 | 储能与滤波 | 电源电路、LC 滤波 |

### 6.4 基础电路识图

#### 1. 读图三问

看任何一张电路图，都先回答三个问题：

1. **电从哪里来** —— 找到 VCC / 3.3V / 5V / 12V，看这条电源线接到了哪些器件；
2. **信号怎么走** —— 从单片机引脚出发跟着线走，确认它连到了目标器件的哪个引脚；
3. **地怎么回去** —— 所有器件的 GND 必须是**同一个 GND**，即共地。

#### 2. 常见符号

| 符号 | 含义 |
| --- | --- |
| VCC / 3V3 / 5V | 电源正极 |
| GND | 公共地 |
| 三角形加竖线 | 二极管（竖线一端为阴极） |
| 三极管 | 三个引脚，箭头方向区分 NPN/PNP |
| 波浪线或方块 | 电阻（方块为常用画法） |
| 两条平行短线 | 电容 |
| 螺旋线 | 电感 |
| 带标注的网络标签 | 同名标签表示同一根导线相连 |

#### 3. 电平标准

| 标准 | 高电平 | 说明 |
| --- | --- | --- |
| **3.3V 逻辑** | 约 3.3V | ESP32-S3 的 IO 电平 |
| **5V 逻辑** | 约 5V | 部分老式模块使用，**不能直接接入 ESP32-S3 的 IO** |
| **开漏输出** | 靠上拉电阻 | 引脚只能主动拉低，输出高电平时为高阻态，I2C 总线即为此结构 |

**5V 模块接到 3.3V 芯片上的三种做法**

| 方法 | 做法 | 适用场合 |
| --- | --- | --- |
| 电阻分压 | 5V 信号经两只电阻分压到约 3.3V | 适合"5V 进 3.3V"的单向信号，速率不能太高 |
| 电平转换模块 | 用现成的双向电平转换板 | 双向通信、速率较高时最省事 |
| 专用转换芯片 | 板上集成单路电平转换芯片 | 批量生产时使用 |

**方向要分清**

- **5V 输出 → 3.3V 输入**：必须降压，否则会烧引脚；
- **3.3V 输出 → 5V 输入**：多数 5V 芯片把 2.4V 以上就当作高电平，通常可以直接连，但要查对方手册确认。

#### 4. 电源树

一块开发板的供电通常分层：

```
USB 5V ──→ LDO / DCDC ──→ 3.3V ──→ 主控芯片、传感器
                          │
12V 电池 ──→ 电机驱动模块 ──→ 直流电机 / 舵机
                          └── 与主控共地
```

**原则**：大功率负载独立供电，但**必须与主控共地**，否则信号没有共同参考点。

#### 5. 四个典型单元电路

| 电路 | 组成 | 要点 |
| --- | --- | --- |
| LED 指示电路 | GPIO → 限流电阻 → LED → GND | 限流电阻不可省略 |
| 按键输入电路 | GPIO ── 按键 ── GND，GPIO 接上拉 | 必须确定默认电平 |
| 三极管驱动电路 | GPIO → 基极电阻 → 三极管 → 负载 | 感性负载并续流二极管 |
| I2C 总线电路 | SDA / SCL 各接 4.7kΩ 上拉到 3.3V | 多设备共享总线 |

#### 6. 接线自检清单

接线完成后，按顺序检查：

1. 电源正负极是否接反；
2. VCC 与 GND 是否共地；
3. 信号线是否接到正确的引脚编号；
4. 通信线是否需要交叉（UART 的 TX 接 RX）；
5. 是否需要上拉电阻（I2C、单总线）；
6. 负载是否需要独立供电。

### 6.5 仿真平台快速验证

在硬件尚未到位或不确定代码逻辑是否正确时，可以先用在线仿真平台验证。

#### 1. 能做什么

- 搭建虚拟 ESP32 开发板，连接 LED、按键、蜂鸣器、电位器、光敏电阻、舵机、I2C/SPI 器件；
- 运行真实的 ESP-IDF 工程代码，查看串口输出与虚拟逻辑分析仪波形；
- 免硬件、免接线，快速验证程序流程与逻辑判断。

#### 2. 不能做什么

- 无法反映真实电路的供电能力、干扰与信号完整性问题；
- 无线通信、摄像头等依赖真实射频与并行接口的功能无法完整仿真；
- 模拟量输入特性与真实传感器存在差异。

#### 3. 使用流程

1. 新建工程，选择目标芯片型号；
2. 拖入所需元件并连线，对照原理图确认引脚；
3. 粘贴或编写程序代码；
4. 编译运行，观察串口输出与元件动作；
5. 逻辑验证通过后，再在实际开发板上复现并做硬件调试。

**定位**：仿真平台用于**验证代码逻辑**，真实开发板用于**验证硬件电路**，两者互补，不能互相替代。

### 6.6 在 ESP-IDF 与 Wokwi 中运行代码

#### 1. 在 ESP-IDF 中运行

```
工程目录/
├── CMakeLists.txt
└── main/
    ├── CMakeLists.txt
    └── main.c          ← 把示例代码粘贴到这里
```

```cmake
# main/CMakeLists.txt
idf_component_register(SRCS "main.c" INCLUDE_DIRS ".")
```

```
idf.py build                     编译，先确认这一步没有报错
idf.py -p COM3 flash             烧录
idf.py -p COM3 monitor           查看串口输出
```

**注意**：示例里用到的组件（如 `esp_camera`、`esp_http_server`）需要在 `main/CMakeLists.txt` 的 `REQUIRES` 中声明，或直接使用乐鑫官方示例工程。

#### 2. 在 Wokwi 中仿真

Wokwi 是浏览器中的在线仿真平台。**它负责"运行"，不负责"编译 ESP-IDF 工程"**，两种使用方式：

| 方式 | 流程 | 说明 |
| --- | --- | --- |
| ESP-IDF 工程 | 本地 `idf.py build` → 用 `wokwi.toml` 指向 `build/*.bin` 与 `build/*.elf` → 在浏览器中运行 | 编译仍在本地，仿真在网页 |
| Arduino 工程 | 直接在浏览器里编写并编译运行 | 适合快速验证 GPIO、ADC 等逻辑 |

`wokwi.toml` 示例：

```toml
[wokwi]
version = 1
firmware = "build/工程名.bin"
elf = "build/工程名.elf"
```

#### 3. Wokwi 能仿真什么、不能仿真什么

| 模块 | 是否支持 | 说明 |
| --- | --- | --- |
| GPIO / LED / 按键 / 继电器 | **支持** | 最常用，拖入元件连线即可 |
| PWM（LEDC） | **支持** | 可观察 LED 亮度变化 |
| 定时器 / FreeRTOS 任务 | **支持** | 逻辑可完整验证 |
| ADC（电位器、光敏） | **支持** | 拖动滑块改变输入电压 |
| UART | **支持** | 有串口监视器，可收发数据 |
| I2C 器件（如 SSD1306、MPU6050） | **支持** | 平台内置虚拟器件 |
| SPI 器件 | **支持** | 需按器件手册连线 |
| **WiFi（STA 连接虚拟热点）** | **支持** | Wokwi 提供虚拟热点 `Wokwi-GUEST`（无密码），设备能拿到 IP |
| 设备之间 UDP / TCP 通信 | 不支持 | 仿真环境里没有第二个真实节点 |
| WiFi 的 AP 热点模式 | 不支持 | 无法模拟"被其它设备连接" |
| **蓝牙 BLE** | **不支持** | 手机搜不到仿真中的设备 |
| **摄像头** | **不支持** | 并行摄像头接口无法仿真 |
| 真实电路问题（供电、干扰、电平） | **不支持** | 仿真反映不出硬件缺陷 |

**结论**：GPIO、ADC、PWM、UART、I2C、SPI、定时器、RTOS，以及 **WiFi（连接 `Wokwi-GUEST`）**，都可以先在 Wokwi 里验证效果；**蓝牙 BLE 与摄像头必须上真实开发板验证**。

#### 4. 推荐的验证顺序

1. **本地编译**：先让 `idf.py build` 通过，解决语法与头文件问题；
2. **逻辑仿真**：在 Wokwi 中验证可仿真模块的程序流程与数值；
3. **硬件验证**：在真实开发板上验证接线、供电、时序与通信。

**三层顺序不能颠倒** —— 先区分"是代码问题还是硬件问题"，再动手改。
