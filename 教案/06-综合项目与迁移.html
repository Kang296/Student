十二、实验安全与操作规范

1. 用电安全

  • 接线、改线操作必须在断电状态下进行。
  • 电机、舵机等大功率负载必须独立供电，且与主控板共地。
  • 严禁将 5V 信号直接接入 3.3V 引脚。
  • 驱动继电器、电机等感性负载必须加续流二极管。

2. 器件保护

  • LED 必须串联限流电阻。
  • I2C 总线必须外接上拉电阻（约 4.7kΩ）。
  • 芯片引脚不得直接驱动超过其电流能力的负载。
  • 拿取开发板时避免徒手接触引脚造成静电损伤。

3. 开发规范

  • 烧录前确认串口号与目标芯片型号。
  • 修改配置后重新完整编译，不依赖增量构建结果。
  • 使用 idf.py monitor 查看崩溃回溯信息，定位异常发生位置。
  • 代码提交前清理调试用的临时打印。

4. 场地与运行安全

  • 电机测试时固定小车或架起驱动轮，防止意外冲出。
  • 无人机项目必须先进行拆桨调试，确认各传感器数据正确后再装机试飞。
  • 飞行测试必须在空旷无人区域进行，并设置紧急停止手段。

十三、衔接 STM32

ESP32-S3 与 STM32 属于同类微控制器，外设原理、总线协议与 RTOS 思想完全相通，差异主要在芯片内部资源与开发工具链。本章按"最小系统 → 外设 → 中断与优先级 → API 对照"的顺序完成迁移。

13.1 最小系统

单片机能正常工作的最小电路由三部分组成：电源、时钟、复位。

部分作用缺一不可的后果
电源提供稳定的 3.3V芯片不启动或反复复位
时钟提供工作节拍程序无法运行，或串口、定时器全部不准
复位提供确定的上电初始状态上电状态不确定，程序跑飞

13.2 时钟树

原理：芯片内部各外设并非工作在同一个频率上。时钟源经倍频得到系统主频，再经各级分频送往不同总线，形成一棵"时钟树"。

典型结构：

外部晶振（HSE 8MHz）──→ PLL 倍频 ──→ 系统时钟（SYSCLK，如 168MHz）
                                        │
                    ┌───────────────────┼───────────────────┐
                    ↓                   ↓                   ↓
              AHB 总线分频        APB1 总线分频        APB2 总线分频
              （内核、DMA、内存）  （定时器、串口）      （GPIO、SPI、ADC）

为什么必须掌握：

  • 串口波特率由 APB 总线时钟分频得到，时钟配错直接表现为串口乱码；
  • 定时器的计时基准来自总线时钟，时钟配错会导致定时与 PWM 频率全部偏离；
  • CubeMX 中配置时钟树时，芯片型号、晶振频率、目标主频三者必须一致。

13.3 复位电路

原理：复位引脚（NRST）在低电平期间使芯片保持复位状态，释放后芯片从起始地址开始执行。

典型电路：NRST 引脚接 10kΩ 上拉到 3.3V，并接 100nF 电容到地。上电瞬间电容电压不能突变，NRST 被短暂拉低，保证芯片在电源稳定后才开始运行。

常见故障：电容容量过大导致复位时间过长，表现为"上电后要等一两秒才开始工作"。

13.4 电源电路

典型设计：

  • 每个电源引脚旁放置 0.1μF 陶瓷电容到地（去耦，滤除高频噪声）；
  • 电源输入端放置 10μF ~ 100μF 电解电容（储能，应对负载突变）；
  • 模拟电源与数字电源通过磁珠或 0Ω 电阻隔离，降低数字电路对 ADC 的干扰。

电源分层原则：

负载类型供电方式注意
主控与传感器3.3V LDO 供电与电机电源共地
直流电机、舵机独立电池供电电流大，不可与主控共用一路
继电器线圈独立 5V/12V 供电必须并续流二极管

13.5 定时器

原理：STM32 的定时器由时钟源、预分频器（PSC）、计数器（CNT）、自动重装载寄存器（ARR）组成。

更新频率 = 定时器时钟 / [(PSC + 1) × (ARR + 1)]

例如定时器时钟 84MHz，要求 1kHz 更新频率：取 PSC = 83（分频后 1MHz），则 ARR = 999。

两种典型用法：

  • 定时中断：周期进入中断服务函数，适合周期性采集与任务调度；
  • PWM 输出：由 ARR 决定周期，由比较寄存器 CCR 决定占空比，适合调光、调速、舵机控制。
/* 启动 PWM 输出 */
HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_1);

/* 修改占空比：CCR 值越大，高电平时间越长 */
__HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_1, 500);

/* 定时中断回调：到点自动进入，函数名不能修改 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
}

13.6 中断

原理：中断是"事件驱动"的执行方式。外设产生中断请求后，CPU 暂停当前程序，跳转执行中断服务函数，执行完毕返回原处继续。

与轮询的对比：

方式实现优点缺点
轮询主循环反复查询标志位实现简单浪费 CPU，事件密集时容易漏检
中断事件触发时自动跳转响应及时，CPU 利用率高需配置优先级，处理函数必须简短

中断服务函数的四条铁律：

  1. 函数必须简短，只做标志位设置或数据入队；
  2. 禁止调用阻塞式接口（HAL_Delay()、vTaskDelay()）；
  3. 共享变量必须加 volatile 修饰，防止编译器优化导致读取到旧值；
  4. 与 RTOS 交互时使用中断安全版本接口。
/* 外部中断回调：按键按下时自动执行 */
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);      /* 只做简单操作 */
}

13.7 优先级

这是最容易记混的地方，务必区分两套体系：

体系规则
STM32 中断优先级（NVIC）数值越小，优先级越高（0 为最高）
FreeRTOS 任务优先级数值越大，优先级越高

其他要点：

  • 中断优先级高于任何任务，除被临界区临时屏蔽外，中断总能抢占任务；
  • NVIC 优先级分为抢占优先级与子优先级，需先通过 HAL_NVIC_SetPriorityGrouping() 设置分组；
  • 多个中断按重要性从 0 开始依次分配，不要全部填 0。
