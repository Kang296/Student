## 七、外设与通信（官方库实现）

### 7.1 GPIO 基础与数字输入输出

#### 1. GPIO 是什么

GPIO 是 General Purpose Input/Output 的缩写，即**通用输入输出**引脚：同一个引脚，既可以配置成输出（去控制别人），也可以配置成输入（去读别人的状态）。

ESP32-S3 共有 40 余个 GPIO，其中大部分可以复用为外设功能。使用任何一个引脚前，必须先明确三件事：

1. **方向**：输入还是输出；
2. **电平**：输出高（1）还是低（0）；
3. **电气特性**：是否需要上拉／下拉，是否需要开漏。

> 这三个词先解释一下：
> **上拉**＝在引脚和电源之间接一个电阻，让引脚默认是**高电平**；
> **下拉**＝在引脚和地之间接一个电阻，让引脚默认是**低电平**；
> **开漏**＝引脚只能主动拉低，不能主动输出高电平，想要高电平必须靠外部上拉电阻。

---

#### 2. 输出模式

输出模式分两种：

- **推挽输出**：能主动输出高电平，也能主动拉低，驱动能力最强，是最常用的输出方式，用于驱动 LED、继电器、蜂鸣器等。
- **开漏输出**：只能主动拉低，输出高电平时引脚处于高阻态，必须依靠**外部上拉电阻**才能得到高电平。I2C 总线必须使用开漏输出，这样多个设备才能共享同一根线而不会互相短路。

> 完整代码见 [第 4 册 · 小车实验一（LED 灯点亮实验）](04-小车开发板实验.html#实验一-led-灯点亮实验)

若需要开漏输出，把方向宏换成 `GPIO_MODE_OUTPUT_OD` 即可，此时高电平必须靠外部上拉电阻提供。

---

#### 3. 输入模式

输入模式分三种，区别在于**引脚悬空时电平是否确定**：

| 模式 | 宏定义 | 悬空时的电平 | 典型用途 |
| --- | --- | --- | --- |
| 浮空输入 | `GPIO_MODE_INPUT` | 不确定，读数随机跳动 | 外部电路已有上下拉 |
| 上拉输入 | `GPIO_MODE_INPUT_PULLUP` | 被内部电阻拉到高电平 | 按键一端接 GND |
| 下拉输入 | `GPIO_MODE_INPUT_PULLDOWN` | 被内部电阻拉到低电平 | 按键一端接 3.3V |

按键的使用方式由接线决定：

- 按键**一端接引脚、一端接 GND** → 用**上拉输入**，平时读到 1，按下读到 0；
- 按键**一端接引脚、一端接 3.3V** → 用**下拉输入**，平时读到 0，按下读到 1。

```c
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "driver/gpio.h"

#define KEY_GPIO   GPIO_NUM_4

void key_init(void)
{
    gpio_config_t cfg = {
        .pin_bit_mask = 1ULL << KEY_GPIO,   // 选中第 4 号引脚（详见第 7 节）
        .mode         = GPIO_MODE_INPUT,
        .pull_up_en   = GPIO_PULLUP_ENABLE,     // 打开内部上拉
        .pull_down_en = GPIO_PULLDOWN_DISABLE,
        .intr_type    = GPIO_INTR_DISABLE,
    };
    gpio_config(&cfg);
}

int key_read(void)
{
    return gpio_get_level(KEY_GPIO);            // 松开读到 1，按下读到 0
}

void app_main(void)
{
    gpio_set_direction(GPIO_NUM_2, GPIO_MODE_OUTPUT);   /* 指示 LED */
    key_init();

    while (1)
    {
        int level = key_read();
        gpio_set_level(GPIO_NUM_2, level ? 0 : 1);      /* 按下时点亮 */
        vTaskDelay(pdMS_TO_TICKS(20));
    }
}
```

**为什么不能随便用浮空输入**：引脚悬空时相当于一根天线，电平随环境变化，程序读到的值在 0 和 1 之间乱跳，看起来像"按键失灵"。只要有按键或开关，就必须给它一个确定的默认电平。

---

#### 4. 上拉与下拉电阻

- **上拉电阻**：把引脚默认电平拉到高；**下拉电阻**：把引脚默认电平拉到低。
- ESP32-S3 内部上下拉电阻约为 45kΩ，属于**弱上拉**，只用于"给定默认电平"，**不能用来驱动负载**。
- 按键、开关这类"开路／闭合"器件，必须依靠上拉或下拉确定默认状态。
- 对上升沿速度有要求的场合（如 I2C 总线在 400kHz 以上），内部弱上拉不够快，必须外接约 **4.7kΩ** 的强上拉。

---

#### 5. 电气特性（必须记住的几条）

- **高电平约 3.3V，低电平约 0V**，属于 3.3V 逻辑，**严禁把 5V 信号直接接入 GPIO**。
- 单个 IO 的输出电流有限（建议不超过 20mA），**不能直接驱动电机、继电器、大功率 LED**，必须通过三极管或 MOS 管。
- 驱动继电器、水泵、电机等**感性负载**时，线圈两端必须**并联续流二极管**，用于吸收断电瞬间的反向电动势。
- 所有外接模块必须与开发板**共地**，否则电平没有共同参考点，通信会时好时坏。

---

#### 6. 引脚复用与恢复

- **引脚复用**是指：同一个物理引脚，通过芯片内部的开关可以被不同外设使用 —— 既能当普通 GPIO，也能交给 UART、I2C、SPI、PWM、ADC。但**同一时刻一个引脚只能归一个外设用**。
- 一个引脚一旦被外设占用（例如 LEDC 输出 PWM、UART 收发、I2C 的 SDA/SCL），它就不再是"普通 GPIO"，此时仅调用 `gpio_set_direction()` 是**抢不回来**的。
- 需要把它还原成普通 GPIO 时，必须先调用 `gpio_reset_pin()`：

```c
#include "driver/gpio.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

#define LED_GPIO   GPIO_NUM_2

void app_main(void)
{
    /* 第一步：把引脚复位，断开之前外设对它的占用 */
    gpio_reset_pin(LED_GPIO);

    /* 第二步：重新配置成普通输出 */
    gpio_set_direction(LED_GPIO, GPIO_MODE_OUTPUT);

    /* 第三步：正常点灯 */
    while (1)
    {
        gpio_set_level(LED_GPIO, 1);
        vTaskDelay(pdMS_TO_TICKS(500));
        gpio_set_level(LED_GPIO, 0);
        vTaskDelay(pdMS_TO_TICKS(500));
    }
}
```

`gpio_reset_pin()` 的实际作用是：关闭中断、打开内部上拉、关闭下拉、关闭输入与输出、把引脚切换回普通 GPIO 功能，并释放外设对该引脚的占用。

**什么时候必须调用它**：

1. 该引脚之前被 LEDC／UART／I2C／SPI／ADC 等外设使用过，现在要当普通 GPIO 用；
2. 同一个引脚在不同实验之间反复改变用途；
3. 需要让引脚回到一个确定状态。

典型的踩坑现象是：代码编译通过、`gpio_set_level()` 也调用了，但引脚电平始终不变 —— 原因就是引脚还被外设占着，没有复位。

**注意**：只做普通的输出控制（例如点亮 LED）时，`gpio_set_direction()` 已经足够，`gpio_reset_pin()` 可以省略。

#### 7. 引脚掩码与 `1ULL`

`gpio_config()` 允许**一次配置多个引脚**，靠的就是"位掩码"：

```c
#include "driver/gpio.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

void app_main(void)
{
    /* 只配置第 4 号引脚 */
    gpio_config_t cfg = {
        .pin_bit_mask = 1ULL << 4,
        .mode         = GPIO_MODE_OUTPUT,
        .pull_up_en   = GPIO_PULLUP_DISABLE,
        .pull_down_en = GPIO_PULLDOWN_DISABLE,
        .intr_type    = GPIO_INTR_DISABLE,
    };
    gpio_config(&cfg);

    /* 同时配置第 4 号和第 42 号引脚，用按位或组合 */
    gpio_config_t cfg2 = {
        .pin_bit_mask = (1ULL << 4) | (1ULL << 42),
        .mode         = GPIO_MODE_OUTPUT,
        .pull_up_en   = GPIO_PULLUP_DISABLE,
        .pull_down_en = GPIO_PULLDOWN_DISABLE,
        .intr_type    = GPIO_INTR_DISABLE,
    };
    gpio_config(&cfg2);

    while (1)
    {
        gpio_set_level(GPIO_NUM_4, 1);
        gpio_set_level(GPIO_NUM_42, 1);
        vTaskDelay(pdMS_TO_TICKS(500));

        gpio_set_level(GPIO_NUM_4, 0);
        gpio_set_level(GPIO_NUM_42, 0);
        vTaskDelay(pdMS_TO_TICKS(500));
    }
}
```

**几句话记住它**：

- `pin_bit_mask` 的类型是 **64 位无符号整数**（`uint64_t`），**每一位对应一个引脚**：第 n 位置 1，就表示要配置第 n 号引脚；
- `1ULL << n` 的作用是把 1 左移到第 n 位，也就是"选中第 n 号引脚"；
- 后缀 **`ULL` 表示"无符号长长整型"，即 64 位** —— ESP32-S3 的引脚号可以超过 31（例如 42），32 位装不下，所以必须写 `ULL`；
- **写成 `1 << 42` 会出错**：左移位数超过了 32 位整数的宽度，结果不确定，引脚实际上没有被配置，而且**编译不会报错**，现象就是"代码没问题但灯不亮"；
- ESP-IDF 提供的宏 `BIT64(n)` 完全等价于 `1ULL << n`，写 `BIT64(42)` 语义更清楚。

**结论**：凡是给 `pin_bit_mask` 赋值，统一写成 `1ULL << 引脚号`，多个引脚用 `|` 连接。

#### 8. 位运算三件套

| 操作 | 写法 | 用途 |
| --- | --- | --- |
| 置位（打开某一位） | `x = x | (1 << n)` | 打开使能、设置标志 |
| 清零（关闭某一位） | `x = x & ~(1 << n)` | 关闭某一位 |
| 取位（判断某一位） | `if (x & (1 << n))` | 读状态寄存器、判断标志位 |

例如判断数据的最高位（第 7 位）是否为 1，以下两种写法等价：

```c
#include "esp_log.h"

static const char *TAG = "bit";

void app_main(void)
{
    unsigned char value = 0;                    /* 一个 8 位的数 */

    /* 1. 置位：把第 0 位和第 2 位变成 1 */
    value = value | (1 << 0);
    value = value | (1 << 2);
    ESP_LOGI(TAG, "after set   : 0x%02X", value);      /* 0x05 */

    /* 2. 取位：判断第 2 位是不是 1 */
    if (value & (1 << 2))
    {
        ESP_LOGI(TAG, "bit 2 is 1");
    }

    /* 3. 清零：把第 0 位变回 0 */
    value = value & ~(1 << 0);
    ESP_LOGI(TAG, "after clear : 0x%02X", value);      /* 0x04 */
}
```

#### 9. 常用 API 一览

| 功能 | 接口 | 说明 |
| --- | --- | --- |
| 设置方向 | `gpio_set_direction(引脚, 模式)` | 单独配置一个引脚的方向 |
| 批量配置 | `gpio_config(&cfg)` | 一次配置方向、上下拉、中断 |
| 输出电平 | `gpio_set_level(引脚, 0/1)` | 写 1 输出高，写 0 输出低 |
| 读取电平 | `gpio_get_level(引脚)` | 返回 0 或 1 |
| 单独设置上下拉 | `gpio_set_pull_mode(引脚, 模式)` | 上拉／下拉／浮空 |
| 复位引脚 | `gpio_reset_pin(引脚)` | 恢复默认状态，释放外设占用 |
**调用流程**

| 步骤 | 调用 | 作用 |
| --- | --- | --- |
| 1 配置一次 | `gpio_config(&cfg)` | 一次把方向、上下拉、中断方式都配好 |
| 2 反复使用 | `gpio_set_level()` / `gpio_get_level()` | 写电平、读电平，写在循环里 |
| 3 用完复位 | `gpio_reset_pin(引脚)` | 换用途前把引脚还原成默认状态 |

> 必须做的只有前两步：**先配置一次，再反复使用**。GPIO 不需要创建句柄，也没有"用完删除"这一步。

#### 10. 注意事项

- `GPIO_NUM_0`、`GPIO_NUM_45`、`GPIO_NUM_46` 属于启动配置引脚（strapping pin —— 芯片上电时会先读这几个引脚的电平，决定从哪里启动），外接电路会改变它的电平、影响启动，使用前需确认电路，**课程实验建议避开**。
- 输出 `1` 表示 3.3V，输出 `0` 表示 0V；务必先确认外接模块是**高电平点亮**还是**低电平点亮**。
- 输入引脚必须确定默认电平（上拉或下拉），不要悬空。
- 给引脚掩码赋值统一使用 `1ULL << n`，不要写成 `1 << n`。
- 复用被外设占用过的引脚时，先调用 `gpio_reset_pin()`。

### 7.2 定时器与 PWM

**先把名词说清楚**

| 名词 | 英文 | 含义 |
| --- | --- | --- |
| PWM | Pulse Width Modulation | 脉冲宽度调制。用"开关的时间比例"去等效控制模拟量，是数字电路控制亮度、转速、角度的通用手段 |
| 周期 | Period（T） | 一个完整"高电平 + 低电平"过程所用的时间 |
| 频率 | Frequency（f） | 每秒完成多少个周期，`f = 1 / T`，单位 Hz |
| 脉宽 | Pulse Width（t_on） | 一个周期内**高电平持续的时间** |
| 占空比 | Duty Cycle（D） | 高电平时间占整个周期的比例，`D = t_on / T`，常用百分数表示 |
| 等效平均电压 | Average Voltage | `U_avg = D × U`。占空比越大，等效电压越高，灯越亮、电机越快 |
| 占空比分辨率 | Duty Resolution | 占空比能分成多少档，由位数决定：n 位 → `2^n` 档，取值范围 `0 ~ 2^n − 1` |
| 定时器 | Timer | LEDC 中负责产生"节奏"的单元，**决定频率与分辨率** |
| 通道 | Channel | LEDC 中负责输出波形的单元，**绑定引脚与占空比** |
| 相位偏移 | hpoint | 指定高电平在一个周期内的起始位置，用于多个通道错开相位 |
| 互补输出 | Complementary Output | 两路反相的波形，用于 H 桥驱动电机（H 桥：四个开关组成的电路，能让电机正转和反转） |
| 死区时间 | Dead Time | 互补输出切换瞬间插入的空白时间，防止上下两个开关管同时导通而短路 |
| 低速 / 高速模式 | Low / High Speed Mode | LEDC 的两种工作模式，低速模式引脚分配更灵活，课程中统一使用低速模式 |

**理解 PWM 只需要三句话**

1. **周期定"多久一次"**，频率是它的倒数 —— 周期越短，频率越高。
2. **占空比定"开多久"**，它决定等效平均电压 —— 占空比越大，输出功率越高。
3. **占空比分辨率定"能调多细"**，由位数决定 —— 位数越高，亮度或转速的调节越平滑。

**关键：频率与分辨率互相制约**

LEDC 的时钟源频率是固定的（APB 总线 80MHz），因此：

```
输出频率 = 时钟源频率 ÷ (分频系数 × 2^占空比位数)
```

也就是说，**想要更高的占空比分辨率（调得更细），就必须牺牲最高频率**：

| 占空比位数 | 占空比档数 | 可达到的最高频率（约） | 典型用途 |
| --- | --- | --- | --- |
| 8 位 | 256 | 312 kHz | 电机调速、小功率调光 |
| 10 位 | 1024 | 78 kHz | LED 调光 |
| 12 位 | 4096 | 19.5 kHz | 高精度调光 |
| 13 位 | 8192 | 9.7 kHz | 兼顾精度与频率 |
| 14 位 | 16384 | 4.9 kHz | 舵机（需要精确的脉宽） |

**占空比数值怎么算**

```
duty = 占空比 × 2^位数
```

| 位数 | 想要 50% 占空比 | 想要 30% 占空比 |
| --- | --- | --- |
| 8 位 | `0.5 × 256 = 128` | `0.3 × 256 ≈ 77` |
| 10 位 | `0.5 × 1024 = 512` | `0.3 × 1024 ≈ 307` |
| 14 位 | `0.5 × 16384 = 8192` | `0.3 × 16384 ≈ 4915` |

**舵机的占空比**：舵机周期固定 20ms（50Hz），1.5ms 对应 90°，占空比 `1.5 / 20 = 7.5%`；用 14 位分辨率时，`duty = 0.075 × 16384 ≈ 1229`。

#### 7.2.1 通用定时器 GPTimer

**原理**：ESP32-S3 内置通用定时器，可设置时钟源、计数方向与分辨率。定时器计数值达到 `alarm_count` 时触发闹钟事件，配合自动重载即可实现精确定时。中断回调运行在中断上下文，耗时操作应交给任务处理。

> 完整代码见 [第 4 册 · 小车实验二（ESP32 定时器实验）](04-小车开发板实验.html#实验二-esp32-定时器实验)

- `resolution_hz = 1000000` 表示 1 个计数单位等于 1 微秒，便于换算。
- `auto_reload_on_alarm = true` 使定时器周期触发；置为 `false` 则只触发一次。

> 中断回调里只适合做"记下时间到了"这件事，真正的处理放到任务里做，理由见 [第 3 册 · 8.4 节「中断配合规范」](03-无线与系统.html#12-中断配合规范)。

**常用 API 与调用流程**

| 步骤 | 调用 | 作用 |
| --- | --- | --- |
| 1 创建 | `gptimer_new_timer(&cfg, &timer)` | 按配置建一个定时器，拿回句柄 |
| 2 设闹钟 | `gptimer_set_alarm_action(timer, &alarm)` | 计数值到 `alarm_count` 时触发，并决定是否自动重载 |
| 3 挂回调 | `gptimer_register_event_callbacks(timer, &cbs, NULL)` | 到点时自动去调用哪个函数 |
| 4 使能 | `gptimer_enable(timer)` | 让定时器能工作；漏掉这一步，启动了也不会触发 |
| 5 启动 | `gptimer_start(timer)` | 开始计数；要暂停用 `gptimer_stop()` |

> 顺序是 **建 → 设 → 挂 → 使能 → 启动**。前四步各做一次，之后到点自动进回调，不用再管它。

#### 7.2.2 LEDC 硬件 PWM

**原理**：LEDC 是硬件 PWM 外设，不占用 CPU。频率与占空比分辨率相互制约：分辨率位数为 `n` 时，占空比范围为 `0 ~ 2^n - 1`；频率越高，可用的分辨率位数越低。

```c
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "driver/ledc.h"

#define PWM_GPIO      GPIO_NUM_2
#define PWM_TIMER     LEDC_TIMER_0
#define PWM_CHANNEL   LEDC_CHANNEL_0

void pwm_init(void)
{
    ledc_timer_config_t timer = {
        .speed_mode      = LEDC_LOW_SPEED_MODE,
        .timer_num       = PWM_TIMER,
        .duty_resolution = LEDC_TIMER_10_BIT,   // 占空比范围 0 ~ 1023
        .freq_hz         = 5000,
        .clk_cfg         = LEDC_AUTO_CLK,
    };
    ledc_timer_config(&timer);

    ledc_channel_config_t ch = {
        .gpio_num   = PWM_GPIO,
        .speed_mode = LEDC_LOW_SPEED_MODE,
        .channel    = PWM_CHANNEL,
        .timer_sel  = PWM_TIMER,
        .duty       = 0,
        .hpoint     = 0,
    };
    ledc_channel_config(&ch);
}

void pwm_set_duty(int duty)          // duty: 0 ~ 1023
{
    ledc_set_duty(LEDC_LOW_SPEED_MODE, PWM_CHANNEL, duty);
    ledc_update_duty(LEDC_LOW_SPEED_MODE, PWM_CHANNEL);
}

void app_main(void)
{
    pwm_init();

    while (1)
    {
        for (int duty = 0; duty <= 1023; duty = duty + 16)   /* 渐亮 */
        {
            pwm_set_duty(duty);
            vTaskDelay(pdMS_TO_TICKS(20));
        }

        for (int duty = 1023; duty >= 0; duty = duty - 16)   /* 渐暗 */
        {
            pwm_set_duty(duty);
            vTaskDelay(pdMS_TO_TICKS(20));
        }
    }
}
```

**关键点**：调用 `ledc_set_duty()` 之后必须调用 `ledc_update_duty()`，新占空比才会生效。

**舵机控制参数**：舵机要求 50Hz 周期（20ms），高电平 0.5ms 对应 0°、1.5ms 对应 90°、2.5ms 对应 180°。使用 14 位分辨率（0~16383）时，对应占空比约为 410、1229、2048。

**常用 API 与调用流程**

| 步骤 | 调用 | 作用 |
| --- | --- | --- |
| 1 配定时器 | `ledc_timer_config(&timer)` | 定频率与占空比位数（决定"节奏"） |
| 2 配通道 | `ledc_channel_config(&ch)` | 把定时器绑到引脚上，并给出初始占空比 |
| 3 改占空比 | `ledc_set_duty()` + `ledc_update_duty()` | 运行时调亮度、转速、角度；两句必须一起写 |

### 7.3 ADC 模数转换

**先把名词说清楚**

| 名词 | 英文 | 含义 |
| --- | --- | --- |
| 模拟量 | Analog | 连续变化的量，如电压、电流、温度、光照强度 |
| 数字量 | Digital | 用有限个离散数字表示的量，如 0 ~ 4095 |
| ADC | Analog-to-Digital Converter | **模数转换器**，把模拟电压转换成数字量 |
| DAC | Digital-to-Analog Converter | **数模转换器**，把数字量转换成模拟电压 |
| 采样 | Sampling | 在某一时刻取一次输入电压的动作 |
| 采样率 | Sample Rate | 每秒采样的次数，单位 Hz。如 1kHz 表示每秒采 1000 次 |
| 采样保持 | Sample and Hold | 采样瞬间把电压存到内部电容上并保持住，供转换期间使用 |
| 量化 | Quantization | 把连续电压归到最接近的刻度上 |
| 量化误差 | Quantization Error | 真实电压与量化结果之间的差，最大为 ±0.5 个 LSB |
| 位数 | Bit / Resolution | ADC 的精度等级，12 位表示有 12 个二进制位 |
| 分辨率 | Resolution | 能分辨的最小电压变化，`满量程 ÷ 2^位数` |
| LSB | Least Significant Bit | **最低有效位**，常用来表示"一个刻度"对应的电压值 |
| 满量程 | Full Scale | 当前档位能测量的最大电压 |
| 参考电压 | Vref | 转换所用的基准电压，ESP32-S3 内部约 1.1V |
| 衰减 | Attenuation | 把量程放大的档位设置，共四档 |
| 逐次逼近 | SAR | Successive Approximation Register，用二分法逐位试探的转换结构 |
| 通道 | Channel | 一个可独立采样的输入引脚（ADC1_CH0 ~ CH9） |
| 单次 / 连续转换 | One-shot / Continuous | 采一次就停 / 不停地连续采样 |
| 有效位数 | ENOB | Effective Number of Bits，扣除噪声后**实际可用**的位数 |
| 校准 | Calibration | 用已知电压修正读数偏差，提高准确性 |
| 滤波 | Filtering | 对多次采样结果做处理，抑制随机噪声 |
| 积分非线性 | INL | 实际转换曲线与理想直线的最大偏差 |
| 微分非线性 | DNL | 每个刻度宽度的不均匀程度 |

**最容易混的两个词：分辨率 与 精度**

- **分辨率**回答"能分到多细" —— 由位数决定，是硬件固定的。
- **精度**回答"分得准不准" —— 由噪声、温漂、参考电压、电路布局决定。

一块 12 位 ADC 在噪声较大的电路上，实际有效精度可能只有 9 ~ 10 位。**位数买不来精度，电路和滤波才能。**

---

#### 1. 原理

**ADC（Analog to Digital Converter，模数转换器）** 负责把连续变化的模拟电压转换成离散的数字量，是单片机读取电位器、光敏电阻、温敏电阻、电池电压等模拟量传感器的唯一途径。

ESP32-S3 内置的 ADC 为 **12 位逐次逼近型（SAR）**。一次完整的转换包含四个步骤：

| 步骤 | 做什么 | 说明 |
| --- | --- | --- |
| 采样 | 把输入电压接到内部采样电容上 | 需要一定的采样时间，输入阻抗过大会采不准 |
| 保持 | 断开输入，保持住这个电压 | 转换期间电压不能变 |
| 量化 | 与内部参考电压逐次比较、二分逼近 | 12 位需要比较 12 次 |
| 编码 | 输出对应的数字量 | 结果范围 0 ~ 4095 |

**逐次逼近的工作方式**：先从最高位开始试探 —— 取满量程的一半与输入比较，大就保留这一位，小就清零，然后对下一位重复同样的动作。12 次比较后即得到 12 位结果，因此转换速度与位数成正比。

**关于采样率**：ADC 完成一次转换需要一定时间，因此每秒能采样的次数有限。根据奈奎斯特定理，要完整还原一个变化的信号，采样率必须**高于信号最高频率的两倍**。这也是为什么采样电位器、光敏这类"缓变信号"时 1kHz 绰绰有余，而采样音频信号就需要专门的 I2S ADC。

#### 2. 分辨率

**分辨率**表示 ADC 能把量程"切成多少份"，由位数决定：

```
刻度数 = 2^位数          12 位 → 2^12 = 4096 个刻度
输出范围 = 0 ~ (2^位数 − 1)   12 位 → 0 ~ 4095
```

**最小可分辨电压（1 个 LSB）** = 满量程 ÷ 4096。不同衰减档位下的对应关系：

| 衰减档位 | 约满量程 | 1 LSB 对应电压 | 适合测量 |
| --- | --- | --- | --- |
| `ADC_ATTEN_DB_0` | 950mV | 约 0.23mV | 小信号、精密传感器 |
| `ADC_ATTEN_DB_2_5` | 1250mV | 约 0.31mV | 中等幅度信号 |
| `ADC_ATTEN_DB_6` | 1750mV | 约 0.43mV | 一般模拟量 |
| `ADC_ATTEN_DB_12` | 2450mV | 约 0.60mV | 光敏、分压电路（最常用） |

**分辨率不是越大越好**：位数越高，1 LSB 越小，但同时也更容易被噪声淹没 —— 这是下面"精度"要解决的问题。

#### 3. 精度

**精度**表示读出来的数值**与真实电压的接近程度**，与分辨率是两个完全不同的概念。

| 概念 | 回答的问题 | 由什么决定 |
| --- | --- | --- |
| 分辨率 | 能分到多细 | 位数（硬件固定 12 位） |
| 精度 | 分得准不准 | 噪声、温漂、参考电压、输入阻抗、电路布局 |

**关键结论：分辨率高不等于精度高。** 一块 12 位 ADC 在噪声较大的电路上，实际有效精度可能只有 9 ~ 10 位（业内称为 **ENOB，有效位数**）。也就是说，即使最小刻度是 0.6mV，读数也可能上下跳动几十毫伏。

**误差来源与对策**：

| 误差来源 | 现象 | 对策 |
| --- | --- | --- |
| 电源与地噪声 | 读数无规律跳动 | 输入端并联 0.1μF 电容，缩短引线，加强接地 |
| 输入阻抗过大 | 读数偏低、不随信号变化 | 用电压跟随器隔离，或降低分压电阻阻值 |
| 参考电压偏差 | 整体读数偏移 | 用万用表实测实际电压做校准系数 |
| 温度漂移 | 冷机与热机读数不同 | 关键场合做温度补偿 |
| 非线性 | 某一区间误差偏大 | 多点标定，查表修正 |
| 采样过快 | 读数互相干扰 | 两次采样之间留出足够间隔 |

**怎么实测精度**（课堂必做的基本功训练）：

1. 用万用表量出实际电压，记下来；
2. 同时记录程序打印的 ADC 原始值与换算电压；
3. 两者相减得到绝对误差，再除以真实值得到相对误差；
4. 连续测 10 组，观察误差是否稳定 —— **误差稳定可以校准，误差乱跳只能靠滤波和改电路**。

#### 4. 参考电压

ADC 的换算基准来自内部参考电压，ESP32-S3 的内部参考电压约为 **1.1V**，且**没有引出外部 Vref 引脚**，无法外接精密基准。

要测量更大的电压，只能通过**衰减档位**把量程放大：

| 衰减档位 | 约可用量程 | 说明 |
| --- | --- | --- |
| `ADC_ATTEN_DB_0` | 0 ~ 950mV | 不衰减 |
| `ADC_ATTEN_DB_2_5` | 0 ~ 1250mV | 约 2.5dB 衰减 |
| `ADC_ATTEN_DB_6` | 0 ~ 1750mV | 约 6dB 衰减 |
| `ADC_ATTEN_DB_12` | 0 ~ 2450mV | 约 12dB 衰减，最常用 |

**电压换算公式**：

```
电压(mV) = 原始值 × 满量程(mV) ÷ 4095
```

**注意两点**：

- 换算时必须使用**当前档位对应的满量程**，用错档位数值会整体偏差；
- 测量 3.3V 以上的电压必须先用电阻**分压**，绝不能直接接入引脚。

**关于 ADC2**：ADC2 与 WiFi **共用同一组硬件资源**，WiFi 工作时会把 ADC2 占住，所以启用 WiFi 后 ADC2 不可用。这不是软件 bug，而是芯片设计如此 —— **联网项目必须使用 ADC1**。

#### 5. 采样（以光敏传感器为例）

光敏电阻的阻值随光照强度变化。要把它变成电压，需要一个**分压电路**：

```
3.3V ──[ 光敏电阻 ]──┬──[ 固定电阻 10kΩ ]── GND
                     │
                   接 ADC 引脚
```

光照增强 → 光敏电阻阻值减小 → 分压点电压升高 → ADC 读数变大。

> 完整代码见 [第 4 册 · 小车实验四（光敏 ADC 采集实验）](04-小车开发板实验.html#实验四-光敏-adc-采集实验)

**实验现象**：用手遮挡光敏电阻时读数明显下降，强光照射时读数上升；读数应在 0 ~ 4095 之间平滑变化，不应出现大幅跳变。

#### 6. 常用 API 与调用流程

| 步骤 | 调用 | 作用 |
| --- | --- | --- |
| 1 建单元 | `adc_oneshot_new_unit(&unit_cfg, &adc_unit)` | 选好用哪一路 ADC，拿回句柄 |
| 2 配通道 | `adc_oneshot_config_channel(adc_unit, 通道, &chan_cfg)` | 指定引脚，并用 `atten` 设置量程 |
| 3 读一次 | `adc_oneshot_read(adc_unit, 通道, &raw)` | 读回原始值，范围 `0 ~ 4095` |
| 4 换算 | `raw / 4095.0f * 3.3f` | 把原始值换算成电压（V） |

> 第 1、2 步初始化时各做一次，第 3 步就是循环里反复调用的那一步。读回来的是**原始值，不是电压**，要自己按第 4 步换算。

#### 7. 提高采样质量的方法

| 方法 | 做法 | 适用场景 |
| --- | --- | --- |
| 多次采样取平均 | 连续读取 8 ~ 16 次后求平均值 | 抑制随机噪声 |
| 滑动平均 | 维护最近 N 次采样的平均值 | 兼顾平滑与响应速度 |
| 中值滤波 | 对 N 次采样排序取中间值 | 剔除脉冲干扰 |
| 硬件滤波 | 输入端并联 0.1μF 电容，缩短引线，加强接地 | 从源头上减小噪声 |

**三种滤波的取舍**：均值滤波最平滑但响应慢；中值滤波抗脉冲最好但需要排序；滑动平均折中。实际使用时可以组合，例如"先去极值再取平均"。

#### 8. DAC 说明

**DAC（Digital to Analog Converter，数模转换器）** 与 ADC 相反，用于把数字量转换为模拟电压输出，可直接输出任意波形或设定电压。

**芯片差异**：经典 ESP32 内置 2 路 8 位 DAC（GPIO25 / GPIO26），而 **ESP32-S3 取消了内置 DAC**。在 ESP32-S3 上需要模拟输出时，采用以下方式：

| 方法 | 原理 | 适用场合 |
| --- | --- | --- |
| PWM + RC 低通滤波 | 用占空比等效平均电压，经 RC 滤波得到平滑电压 | 精度要求不高的设定电压 |
| 外接 SPI / I2C DAC 芯片 | 通过总线发送数字量，由专用芯片输出模拟电压 | 需要较高精度或高速波形 |
| I2S + 音频 DAC | 由 I2S 外设输出数字音频流 | 播放音频 |

**典型应用**：设定基准电压、产生低频波形、控制模拟调光与模拟量输出模块。

### 7.4 UART 串口通信

#### 原理

UART 为异步串行通信，两端必须约定相同的**波特率、数据位、校验位与停止位**，并且必须共地。

| 参数 | 含义 | 常用值 |
| --- | --- | --- |
| 波特率 | 每秒传输多少位 | 9600 / 115200 |
| 数据位 | 一个字符用几位表示 | 8 位 |
| 校验位 | 用于发现传输错误的附加位 | 不用（None） |
| 停止位 | 一个字符结束的标志 | 1 位 |

**"异步"是什么意思**：UART 没有单独的时钟线，接收方全靠**约定的波特率**自己推算每一位的时间宽度。所以两端波特率必须一致，差一点就会全是乱码。

**接线只有两条规矩**

- **TX 接对方的 RX，RX 接对方的 TX**（交叉接线）—— 发送端要接到接收端，两根同名的线接在一起是收不到数据的；
- **两块板子的 GND 必须连在一起**（共地）—— "高电平"是相对地线而言的，没有共同的 0V 参考点，就无法判断谁高谁低。板载 USB 转串口芯片默认连接 `UART0`，`printf` 的输出会重定向到该端口，用于日志输出；业务串口应使用 `UART1` 或 `UART2`，避免与日志混在一起。

#### 官方 API 用法

> 完整代码见 [第 4 册 · 小车实验三（ESP32 UART 实验）](04-小车开发板实验.html#实验三-esp32-uart-实验)
**常用 API 与调用流程**

| 步骤 | 调用 | 作用 |
| --- | --- | --- |
| 1 定参数 | `uart_param_config(端口, &cfg)` | 设波特率、数据位、校验位、停止位 |
| 2 定引脚 | `uart_set_pin(端口, TX, RX, RTS, CTS)` | 把外设引到具体引脚；不用流控就填 `UART_PIN_NO_CHANGE` |
| 3 装驱动 | `uart_driver_install(端口, 收缓冲, 发缓冲, 事件队列深度, &队列, 中断标志)` | 申请收发缓冲区、起接收任务；装完才能收发 |
| 4 收发 | `uart_write_bytes()` / `uart_read_bytes()` | 发一串字节、收一串字节（带超时） |

> 第 1、2、3 步顺序不能颠倒，各做一次；第 4 步才是循环里反复用的那一步。

#### 轮询接收与中断接收

- **轮询接收**：在主循环中调用 `uart_read_bytes()`，带超时参数；实现简单，但实时性一般。
- **中断接收**：`uart_driver_install()` 时传入事件队列，接收任务阻塞在 `xQueueReceive()` 上，事件到达后读取数据；实时性好，适合协议解析。
- **自收发测试**：将 TXD 与 RXD 用杜邦线短接，发送的数据会被自己接收，用于验证串口配置是否正确。

#### 数据类型与粘包问题

串口传的是一串**字节**，它不保留任何"消息边界"，于是会出现两个真实问题：

- **粘包**：发送方连发两帧，接收方一次 `uart_read_bytes()` 把两帧一起读进来；
- **分包**：一帧太长，一次只读到半帧。

**结论：一次 read 不等于一帧。**

**解决办法：设计一个带帧头和长度的固定格式**，接收端逐字节解析。例如：

```
帧头(2)   长度(1)  命令(1)  数据(N)   校验(1)  帧尾(1)
AA 55      N       CMD      ...       SUM      0D
```

接收端用**状态机**解析。所谓状态机，就是**用一个变量记住"现在收到第几步了"，每来一个字节就按规则决定跳到哪一步**。它一次只处理一个字节：

| 当前状态 | 做什么 | 满足条件后 |
| --- | --- | --- |
| 等帧头 1 | 找 `0xAA` | 进入「等帧头 2」 |
| 等帧头 2 | 判断是不是 `0x55`，不是就退回上一步 | 进入「收长度」 |
| 收长度 | 记下这一帧的数据长度 N | 进入「收数据」 |
| 收数据 | 连续收 N 个字节 | 进入「校验」 |
| 校验 | 累加和对不对 | 对上就交给业务处理；不对就整帧丢弃，退回最初状态 |

**为什么用状态机**：它既不怕粘包也不怕分包 —— 字节一个一个喂进去，半帧就停在中间状态等着，下一批字节到了接着处理。

收发流程的完整代码见[第 4 册「小车实验三」](04-小车开发板实验.html#实验三-esp32-uart-实验)。

### 7.5 单总线时序传感器（DHT11）

#### 原理

DHT11 使用一根数据线通信，通过高低电平的持续时间区分数据位：

- 主机发起始信号：拉低总线至少 18ms，然后释放。
- 从机响应：拉低约 80μs，再拉高约 80μs。
- 数据位判定：每个位以 50μs 低电平开始，随后高电平持续约 26~28μs 表示 0，持续约 70μs 表示 1。
- 数据传输 40 位：湿度整数、湿度小数、温度整数、温度小数、校验和，前四字节之和的低 8 位应等于校验和。

**时序敏感性**：该协议依赖微秒级时序，任务切换或中断抢占都会导致读取失败。**原因**：协议靠"高电平持续 26μs 还是 70μs"来区分 0 和 1，如果读到一半被中断打断，程序回来时已经过去了几十微秒，这一位就会判错 —— 而**一位错会导致后面所有位全部错位**，整帧数据作废。微秒延时必须使用 `esp_rom_delay_us()`，不能使用 `vTaskDelay()`（最小粒度为 1 个 Tick）。

#### 官方 API 实现

> 完整代码见 [第 4 册 · 小车实验九（DHT11 温湿度采集实验）](04-小车开发板实验.html#实验九-dht11-温湿度采集实验)
**DHT11 没有官方驱动**：单总线是厂家自定义的时序，不属于芯片的标准外设，官方库不提供接口，只能照着上面的时序自己操纵 GPIO。

| 步骤 | 做什么 | 关键调用 |
| --- | --- | --- |
| 1 起始 | 引脚切输出，拉低 ≥18ms，再拉高释放 | `gpio_set_direction()` + `gpio_set_level()` |
| 2 等响应 | 切输入，等从机拉低 80μs、再拉高 80μs | 循环 `gpio_get_level()` 等待 |
| 3 读 40 位 | 每位先低 50μs，再看高电平持续多久：约 26~28μs 是 0，约 70μs 是 1 | `gpio_get_level()` + `esp_rom_delay_us()` |
| 4 校验 | 前 4 字节求和取低 8 位，应等于第 5 字节 | 纯计算，不碰硬件 |
| 5 收尾 | 引脚恢复为输入并置高，等下一次读取 | `gpio_set_direction()` |

> 全程只用一个引脚，在"输出发起始信号"和"输入读数据"之间来回切换；所有延时必须用微秒级的 `esp_rom_delay_us()`。

#### 注意事项

- 数据线必须外接约 4.7kΩ 上拉电阻到 3.3V。
- 两次读取之间间隔不少于 1 秒。
- 读取失败时应重试并记录失败次数，而不是直接采用错误数据。

### 7.6 I2C 总线

#### 原理

I2C 使用 SCL（时钟）与 SDA（数据）两根线，均为开漏输出，必须外接上拉电阻（典型 4.7kΩ）。总线上可挂接多个设备，每个设备有唯一的 7 位地址。通信过程为：起始条件 → 设备地址 + 读写位 → 应答 → 寄存器地址 → 数据传输 → 停止条件。逐个解释：

- **起始条件（S）**：主机先把数据线拉低，再把时钟线拉低，告诉总线上所有设备"我要开始说话了"；
- **设备地址 + 读写位**：主机报出要找的门牌号，末位表示这次是读还是写；
- **应答（ACK）**：被点名的设备把数据线拉低一下表示"我在，收到了"；如果没人应答就是 **NACK**，通常说明地址写错或设备没接好；
- **寄存器地址**：告诉对方要访问它内部的哪个"抽屉"；
- **重复起始（Sr）**：不先发停止条件、直接再发一次起始条件，用于"写完寄存器地址就马上读数据"这种连贯操作；
- **停止条件（P）**：时钟线为高时把数据线由低变高，表示通信结束。

绝大多数传感器采用"寄存器模型"：写配置寄存器，读数据寄存器。调试顺序应为：先扫描总线上的设备地址，再读身份寄存器（如 `WHO_AM_I`）确认型号，最后读取业务数据。

#### 官方 API（新驱动）

```c
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

#include "driver/i2c_master.h"
#include "esp_log.h"

#define I2C_PORT    I2C_NUM_0
#define I2C_SDA     GPIO_NUM_41
#define I2C_SCL     GPIO_NUM_42
#define DEV_ADDR    0x68                      // 7 位地址

static const char *TAG = "i2c";
static i2c_master_bus_handle_t s_bus = NULL;
static i2c_master_dev_handle_t s_dev = NULL;

void i2c_init(void)
{
    i2c_master_bus_config_t bus_cfg = {
        .i2c_port            = I2C_PORT,
        .sda_io_num          = I2C_SDA,
        .scl_io_num          = I2C_SCL,
        .clk_source          = I2C_CLK_SRC_DEFAULT,
        .glitch_ignore_cnt   = 7,
        .flags.enable_internal_pullup = true,
    };
    i2c_new_master_bus(&bus_cfg, &s_bus);

    i2c_device_config_t dev_cfg = {
        .dev_addr_length = I2C_ADDR_BIT_LEN_7,
        .device_address  = DEV_ADDR,
        .scl_speed_hz    = 400000,
    };
    i2c_master_bus_add_device(s_bus, &dev_cfg, &s_dev);
}

/* 读寄存器：先写寄存器地址，再读回数据 */
esp_err_t i2c_read_reg(uint8_t reg, uint8_t *buf, size_t len)
{
    return i2c_master_transmit_receive(s_dev, &reg, 1, buf, len, 1000);
}

/* 写寄存器 */
esp_err_t i2c_write_reg(uint8_t reg, const uint8_t *buf, size_t len)
{
    uint8_t tmp[8];
    tmp[0] = reg;
    for (size_t i = 0; i < len && i < 7; i++)
    {
        tmp[i + 1] = buf[i];
    }
    return i2c_master_transmit(s_dev, tmp, len + 1, 1000);
}

/* 扫描总线（探测某个地址上是否有设备） */
void i2c_scan(void)
{
    for (uint8_t addr = 0x08; addr < 0x78; addr++)
    {
        if (i2c_master_probe(s_bus, addr, 100) == ESP_OK)
        {
            ESP_LOGI(TAG, "found device at 0x%02X", addr);
        }
    }
}

void app_main(void)
{
    i2c_init();

    ESP_LOGI(TAG, "scanning i2c bus...");
    i2c_scan();

    uint8_t id = 0;

    while (1)
    {
        if (i2c_read_reg(0x75, &id, 1) == ESP_OK)
        {
            ESP_LOGI(TAG, "WHO_AM_I = 0x%02X", id);
        }
        else
        {
            ESP_LOGE(TAG, "device not found");
        }

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}
```

**常用 API 与调用流程**

| 步骤 | 调用 | 作用 |
| --- | --- | --- |
| 1 建总线 | `i2c_new_master_bus(&bus_cfg, &s_bus)` | 指定 SDA / SCL 引脚，拿回**总线句柄** |
| 2 挂设备 | `i2c_master_bus_add_device(s_bus, &dev_cfg, &s_dev)` | 指定器件地址与速率，拿回**设备句柄** |
| 3 收发 | `i2c_master_transmit()` / `i2c_master_transmit_receive()` | 写数据；或先写寄存器地址再读回数据 |
| 4 释放 | `i2c_master_bus_rm_device()` / `i2c_del_master_bus()` | 换设备、或初始化失败时用，实验里一般不用管 |

> 两个句柄的关系：**总线句柄代表"这条线"**，一条线上可以挂很多器件；**设备句柄代表"线上某一个器件"**，每次收发用的都是设备句柄。所以第 1、2 步各做一次，第 3 步才是循环里的那一步。

### 7.7 SPI 总线

#### 原理

SPI 使用 SCK（时钟）、MOSI（主发从收）、MISO（主收从发）、CS（片选）四根线，全双工通信，速度高于 I2C。

**为什么比 I2C 快**：I2C 是开漏输出，高电平靠上拉电阻"拉"上去，上升沿慢，速度被限制在几百 kHz 到 1MHz；SPI 是推挽输出，高低电平都主动驱动，能轻松跑到几十 MHz。而且 I2C 每传一个字节都要额外传地址和应答位，开销也更大。关键参数为时钟极性与相位（CPOL/CPHA）组成的四种模式，以及时钟频率和片选引脚。

- **CPOL（时钟极性）**：时钟线空闲时是高电平还是低电平；
- **CPHA（时钟相位）**：在时钟的第几个边沿采样数据。

两者各 2 种取值，组合起来就是 4 种模式（模式 0~3）。**接一个器件前必须先查手册确认它用哪种模式**，配错就会读出全 0 或全 0xFF。一条总线可挂接多个从设备，每个设备使用独立的片选引脚。

#### 官方 API 用法

> 完整代码见 [第 5 册 · 无人机实验三（PMW3901 光流 SPI 采集实验）](05-无人机开发板实验.html#实验三-pmw3901-光流传感器-spi-采集实验)
**常用 API 与调用流程**

| 步骤 | 调用 | 作用 |
| --- | --- | --- |
| 1 建总线 | `spi_bus_initialize(主机号, &bus_cfg, SPI_DMA_CH_AUTO)` | 指定 SCLK / MOSI / MISO，初始化一条 SPI 总线 |
| 2 挂设备 | `spi_bus_add_device(主机号, &dev_cfg, &dev)` | 指定片选引脚、时钟频率、模式（CPOL / CPHA），拿回设备句柄 |
| 3 收发 | `spi_device_transmit(dev, &trans)` | 填好 `tx_buffer` / `rx_buffer` 与长度，一次把收发做完 |
| 4 释放 | `spi_bus_remove_device()` / `spi_bus_free()` | 换设备时用，实验里一般不用管 |

> 和 I2C 一样是**先建总线、再挂设备**，区别是 SPI 要四根线以上（时钟、两根数据线、每个器件一根片选）。`spi_device_transmit()` 一次就把发送和接收都做完 —— SPI 是全双工，发出去的同时就在收。

#### 传感器读取示例（SPL06-001 气压计）

> 完整代码见 [第 5 册 · 无人机实验五（SPL06-001 气压计 SPI 采集实验）](05-无人机开发板实验.html#实验五-spl06-001-气压计-spi-采集实验)

#### 常见问题

- 读回全 0 或全 0xFF：模式（CPOL/CPHA）配置错误、片选未拉低、时钟频率超过器件上限。
- 多设备共用总线时，每个设备必须使用独立片选引脚。
- `length` 字段的单位是**比特**，不是字节。

### 7.8 显示模块：OLED 与 TFT

显示模块是嵌入式系统中最常用的本地人机界面。本节只讲两类典型器件的接口与驱动要点，具体字库与图形库由实验提供。

#### 1. OLED（I2C 接口）

- **典型器件**：SSD1306，分辨率 128×64，I2C 地址通常为 `0x3C`（部分模块为 `0x3D`）。
- **接法**：VCC 接 3.3V，GND 接地，SCL / SDA 接 I2C 总线，两根线各接 4.7kΩ 上拉电阻。
- **显示原理**：显存按**页（Page）与列（Column）**组织，共 8 页、每页 8 行像素。写入数据后列地址自动递增。
- **操作方式**：写**命令**与写**数据**通过控制字节区分，均走 I2C 总线。

```c
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "driver/i2c_master.h"
#include "esp_log.h"

static const char *TAG = "oled";

#define OLED_ADDR   0x3C
#define OLED_CTRL_CMD  0x00          /* 控制字节：后面跟的是命令 */
#define OLED_CTRL_DATA 0x40          /* 控制字节：后面跟的是数据 */

static i2c_master_dev_handle_t s_oled = NULL;

/* 发送一条命令 */
void oled_write_cmd(uint8_t cmd)
{
    uint8_t buf[2] = { OLED_CTRL_CMD, cmd };
    i2c_master_transmit(s_oled, buf, 2, 1000);
}

/* 发送一段显存数据 */
void oled_write_data(const uint8_t *data, size_t len)
{
    uint8_t buf[129];

    buf[0] = OLED_CTRL_DATA;
    for (size_t i = 0; i < len && i < 128; i++)
    {
        buf[i + 1] = data[i];
    }
    i2c_master_transmit(s_oled, buf, len + 1, 1000);
}

/* 说明：要显示文字需要先取模生成点阵数组，此处用点阵图案演示写入流程。 */
static const uint8_t s_logo[8] = { 0x3C, 0x42, 0x81, 0x81, 0x81, 0x81, 0x42, 0x3C };

void app_main(void)
{
    /* 初始化 I2C 总线并挂载 OLED */
    i2c_master_bus_config_t bus_cfg = {
        .i2c_port          = I2C_NUM_0,
        .sda_io_num        = GPIO_NUM_8,
        .scl_io_num        = GPIO_NUM_9,
        .clk_source        = I2C_CLK_SRC_DEFAULT,
        .glitch_ignore_cnt = 7,
        .flags.enable_internal_pullup = true,
    };
    i2c_master_bus_handle_t bus = NULL;
    i2c_new_master_bus(&bus_cfg, &bus);

    i2c_device_config_t dev_cfg = {
        .dev_addr_length = I2C_ADDR_BIT_LEN_7,
        .device_address  = OLED_ADDR,
        .scl_speed_hz    = 400000,
    };
    i2c_master_bus_add_device(bus, &dev_cfg, &s_oled);

    /* 初始化序列：关显示 → 设置页寻址 → 清屏 → 开显示 */
    oled_write_cmd(0xAE);
    oled_write_cmd(0x20);
    oled_write_cmd(0x02);

    for (int page = 0; page < 8; page++)
    {
        oled_write_cmd(0xB0 + page);
        oled_write_cmd(0x00);
        oled_write_cmd(0x10);
        oled_write_data(s_logo, 8);
    }

    oled_write_cmd(0xAF);
    ESP_LOGI(TAG, "oled init done");

    while (1)
    {
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}
```

- **汉字显示**：需要先用取模软件生成点阵数组，再按页写入显存。
- **工程建议**：实际项目中使用成熟的图形库（如 `u8g2`、`esp_lcd` 配套驱动），不要从零实现字库。

**常用 API 与调用流程**

| 步骤 | 调用 | 作用 |
| --- | --- | --- |
| 1 建总线 + 挂设备 | `i2c_new_master_bus()` → `i2c_master_bus_add_device()` | 与 7.6 相同，拿回 OLED 的设备句柄 |
| 2 发命令 | `i2c_master_transmit()`，第 1 个字节填 `0x00` | 设置页地址、清屏、开关显示 |
| 3 发数据 | `i2c_master_transmit()`，第 1 个字节填 `0x40` | 写显存，128×64 共 8 页、每页 8 行 |
| 4 刷新 | 重复第 2、3 步 | 屏幕上要变化的内容，每次都得重新写一遍 |

> 关键只有一句：**命令和数据走同一条 I2C 线，靠第 1 个"控制字节"区分**（`0x00` 是命令，`0x40` 是数据）。

---
#### 2. TFT 彩屏（SPI 接口）

**典型器件**：ILI9341（2.4 寸，240×320）、ST7789（1.3 / 1.8 寸）。两者都是 SPI 接口，区别在于驱动支持：

| 器件 | ESP-IDF 官方驱动 | Wokwi 仿真 |
| --- | --- | --- |
| **ILI9341** | 无官方 `esp_lcd` 面板驱动，需按命令表自行初始化 | **支持**（元件 `wokwi-ili9341`） |
| ST7789 | 有官方驱动 `esp_lcd_new_panel_st7789()` | 不支持 |

本节以 **ILI9341** 为例，因为它是唯一能在 Wokwi 里跑起来的彩屏。

**控制引脚**

- `SCK / MOSI / CS`：SPI 总线；只写不读，MISO 不用接
- `DC`：数据 / 命令选择 —— 低电平表示接下来发的是命令，高电平表示发的是数据
- `RST`：复位引脚，初始化前必须先复位
- `LED`：背光，不接则黑屏

**驱动思路**

ILI9341 没有官方驱动，但官方 `esp_lcd` 提供了两个底层接口：

- `esp_lcd_panel_io_tx_param()` —— 发送一条命令和它的参数
- `esp_lcd_panel_io_tx_color()` —— 发送显存数据

按数据手册的命令表把初始化序列发一遍，再写显存，屏幕就亮了。

**Wokwi 接线**

| wokwi-ili9341 引脚 | 接到 ESP32-S3 |
| --- | --- |
| VCC | 3.3V |
| GND | GND |
| CS | GPIO10 |
| RST | GPIO14 |
| D/C | GPIO9 |
| MOSI | GPIO11 |
| SCK | GPIO12 |
| LED | GPIO13 |

**完整示例**

```c
#include "driver/gpio.h"
#include "driver/spi_master.h"
#include "esp_lcd_panel_io.h"
#include "esp_heap_caps.h"
#include "esp_log.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

/* ===== 引脚定义（按实际接线修改）=====
   与 Wokwi 的 wokwi-ili9341 元件一一对应：
   CS -> 片选   DC -> 数据/命令   RST -> 复位
   SCK -> 时钟  MOSI -> 数据      LED -> 背光 */
#define PIN_SCLK    GPIO_NUM_12
#define PIN_MOSI    GPIO_NUM_11
#define PIN_CS      GPIO_NUM_10
#define PIN_DC      GPIO_NUM_9
#define PIN_RST     GPIO_NUM_14
#define PIN_LED     GPIO_NUM_13

#define LCD_W       240                 /* 屏幕宽（像素） */
#define LCD_H       320                 /* 屏幕高（像素） */
#define STRIP       20                  /* 每次刷新 20 行，省内存 */

static const char *TAG = "tft";

/* 把 8 位的红、绿、蓝合成为一个 16 位颜色值（RGB565） */
static uint16_t color565(int r, int g, int b)
{
    return (uint16_t)(((r & 0xF8) << 8) | ((g & 0xFC) << 3) | (b >> 3));
}

/* 设置要写入的矩形区域：先写列地址，再写行地址，坐标是"起点 ~ 终点"，都包含在内 */
static void lcd_set_window(esp_lcd_panel_io_handle_t io,
                           int x0, int y0, int x1, int y1)
{
    uint8_t col[4] = { x0 >> 8, x0 & 0xFF, x1 >> 8, x1 & 0xFF };
    uint8_t row[4] = { y0 >> 8, y0 & 0xFF, y1 >> 8, y1 & 0xFF };

    esp_lcd_panel_io_tx_param(io, 0x2A, col, 4);   /* 命令 0x2A：列地址 */
    esp_lcd_panel_io_tx_param(io, 0x2B, row, 4);   /* 命令 0x2B：行地址 */
}

/* 用纯色填充一个矩形区域 */
static void lcd_fill(esp_lcd_panel_io_handle_t io, uint16_t *buf,
                     int x0, int y0, int x1, int y1, uint16_t color)
{
    int w = x1 - x0 + 1;
    int h = y1 - y0 + 1;

    /* ILI9341 要求先发高字节，所以要交换一下字节顺序 */
    uint16_t be = (uint16_t)((color >> 8) | (color << 8));

    for (int i = 0; i < w * h; i++)
    {
        buf[i] = be;
    }

    lcd_set_window(io, x0, y0, x1, y1);
    esp_lcd_panel_io_tx_color(io, 0x2C, buf, w * h * 2);   /* 命令 0x2C：写显存 */
}

/* ILI9341 初始化序列 */
static void lcd_init_ili9341(esp_lcd_panel_io_handle_t io)
{
    uint8_t p[15];

    p[0] = 0x00; p[1] = 0xC1; p[2] = 0x30;
    esp_lcd_panel_io_tx_param(io, 0xCF, p, 3);

    p[0] = 0x64; p[1] = 0x03; p[2] = 0x12; p[3] = 0x81;
    esp_lcd_panel_io_tx_param(io, 0xED, p, 4);

    p[0] = 0x85; p[1] = 0x10; p[2] = 0x7A;
    esp_lcd_panel_io_tx_param(io, 0xE8, p, 3);

    p[0] = 0x39; p[1] = 0x2C; p[2] = 0x00; p[3] = 0x34; p[4] = 0x02;
    esp_lcd_panel_io_tx_param(io, 0xCB, p, 5);

    p[0] = 0x20;
    esp_lcd_panel_io_tx_param(io, 0xF7, p, 1);

    p[0] = 0x00; p[1] = 0x00;
    esp_lcd_panel_io_tx_param(io, 0xEA, p, 2);

    p[0] = 0x23;                                        /* 电源控制 1 */
    esp_lcd_panel_io_tx_param(io, 0xC0, p, 1);

    p[0] = 0x10;                                        /* 电源控制 2 */
    esp_lcd_panel_io_tx_param(io, 0xC1, p, 1);

    p[0] = 0x3E; p[1] = 0x28;                           /* VCOM 控制 1 */
    esp_lcd_panel_io_tx_param(io, 0xC5, p, 2);

    p[0] = 0x86;                                        /* VCOM 控制 2 */
    esp_lcd_panel_io_tx_param(io, 0xC7, p, 1);

    p[0] = 0x48;                                        /* 显示方向：竖屏 + BGR */
    esp_lcd_panel_io_tx_param(io, 0x36, p, 1);

    p[0] = 0x55;                                        /* 像素格式：16 位 RGB565 */
    esp_lcd_panel_io_tx_param(io, 0x3A, p, 1);

    p[0] = 0x00; p[1] = 0x18;
    esp_lcd_panel_io_tx_param(io, 0xB1, p, 2);

    p[0] = 0x08; p[1] = 0x82; p[2] = 0x27;
    esp_lcd_panel_io_tx_param(io, 0xB6, p, 3);

    esp_lcd_panel_io_tx_param(io, 0x11, NULL, 0);       /* 退出睡眠 */
    vTaskDelay(pdMS_TO_TICKS(120));

    esp_lcd_panel_io_tx_param(io, 0x29, NULL, 0);       /* 打开显示 */
    vTaskDelay(pdMS_TO_TICKS(50));
}

void app_main(void)
{
    /* 1. 初始化 SPI 总线 */
    spi_bus_config_t bus_cfg = {
        .sclk_io_num     = PIN_SCLK,
        .mosi_io_num     = PIN_MOSI,
        .miso_io_num     = -1,                     /* 只写不读 */
        .quadwp_io_num   = -1,
        .quadhd_io_num   = -1,
        .max_transfer_sz = LCD_W * STRIP * sizeof(uint16_t),
    };
    ESP_ERROR_CHECK(spi_bus_initialize(SPI2_HOST, &bus_cfg, SPI_DMA_CH_AUTO));

    /* 2. 建立 LCD 的 SPI 接口（告诉 esp_lcd：CS、DC 是哪两根，时钟多快） */
    esp_lcd_panel_io_handle_t io = NULL;
    esp_lcd_panel_io_spi_config_t io_cfg = {
        .cs_gpio_num       = PIN_CS,
        .dc_gpio_num       = PIN_DC,
        .spi_mode          = 0,
        .pclk_hz           = 20 * 1000 * 1000,     /* 20MHz */
        .trans_queue_depth = 10,
        .lcd_cmd_bits      = 8,
        .lcd_param_bits    = 8,
    };
    ESP_ERROR_CHECK(esp_lcd_new_panel_io_spi((esp_lcd_spi_bus_handle_t)SPI2_HOST,
                                             &io_cfg, &io));

    /* 3. 硬件复位 */
    gpio_set_direction(PIN_RST, GPIO_MODE_OUTPUT);
    gpio_set_level(PIN_RST, 1);
    vTaskDelay(pdMS_TO_TICKS(10));
    gpio_set_level(PIN_RST, 0);
    vTaskDelay(pdMS_TO_TICKS(20));
    gpio_set_level(PIN_RST, 1);
    vTaskDelay(pdMS_TO_TICKS(120));

    /* 4. 写入初始化序列 */
    lcd_init_ili9341(io);

    /* 5. 打开背光 */
    gpio_set_direction(PIN_LED, GPIO_MODE_OUTPUT);
    gpio_set_level(PIN_LED, 1);

    ESP_LOGI(TAG, "ILI9341 ready, %dx%d", LCD_W, LCD_H);

    /* 6. 申请一块 DMA 可以访问的缓冲区 */
    uint16_t *buf = heap_caps_malloc(LCD_W * STRIP * sizeof(uint16_t), MALLOC_CAP_DMA);
    if (buf == NULL)
    {
        ESP_LOGE(TAG, "no memory for buffer");
        return;
    }

    /* 7. 循环刷红、绿、蓝三种颜色 */
    while (1)
    {
        uint16_t colors[3] = {
            color565(255, 0, 0),        /* 红 */
            color565(0, 255, 0),        /* 绿 */
            color565(0, 0, 255),        /* 蓝 */
        };

        for (int c = 0; c < 3; c++)
        {
            for (int y = 0; y < LCD_H; y += STRIP)
            {
                int y1 = y + STRIP - 1;
                if (y1 > LCD_H - 1)
                {
                    y1 = LCD_H - 1;
                }
                lcd_fill(io, buf, 0, y, LCD_W - 1, y1, colors[c]);
            }
            vTaskDelay(pdMS_TO_TICKS(1000));
        }
    }
}
```

**常用 API 与调用流程**

| 步骤 | 调用 | 作用 |
| --- | --- | --- |
| 1 建 SPI 总线 | `spi_bus_initialize()` | 配好 SCLK / MOSI，只写不读可不接 MISO |
| 2 建 LCD 接口 | `esp_lcd_new_panel_io_spi()` | 告诉 esp_lcd：CS、DC 是哪两根，时钟多快 |
| 3 硬件复位 | `gpio_set_level()` 拉低 RST 再拉高 | 屏幕要求的上电复位时序 |
| 4 写初始化序列 | `esp_lcd_panel_io_tx_param()` 按命令表逐条下发 | 设置方向、颜色格式、扫描方式等 |
| 5 开背光 | `gpio_set_level()` 把 LED 置高 | 不点这一下，屏幕始终是黑的 |
| 6 画图 | `esp_lcd_panel_io_tx_color()` 推送像素数据 | 先用 `0x2A` / `0x2B` 定好矩形区域，再送颜色 |

> 相比 OLED，TFT 多了**复位**和**初始化序列**两步：屏幕出厂后必须把厂商给的寄存器配置一条条写进去，它才知道按什么方向、什么颜色格式显示。这一步没有通用写法，只能照搬厂商或驱动库给的命令表。
**实验现象**：屏幕依次整屏刷红、绿、蓝，每种颜色停留 1 秒。

| 对比项 | OLED（SSD1306） | TFT（ILI9341） |
| --- | --- | --- |
| 接口 | I2C，两根线 | SPI，四根线以上 |
| 分辨率 | 128×64 | 240×320 |
| 颜色 | 单色 | 彩色 |
| 刷新速度 | 较慢 | 快 |
| 适用场景 | 显示数值、状态、简单菜单 | 显示图片、波形、图形界面 |
| 难点 | 字模与页寻址 | 引脚多、初始化命令多 |

#### 3. 调试顺序

1. 先确认背光能点亮（TFT）或屏幕能清屏（OLED）；
2. 再扫描 I2C 地址 / 抓 SPI 波形，确认通信正常；
3. 最后逐步实现"画点 → 画线 → 显示字符 → 显示变量"。

### 7.9 执行器驱动

执行器是嵌入式系统的"输出端"。不同执行器的驱动电路与驱动方式差异很大，本节统一梳理。

| 执行器 | 驱动方式 | 驱动电路要求 | 关键参数 |
| --- | --- | --- | --- |
| LED | GPIO 直驱 | 串联限流电阻 | 正向压降、工作电流 |
| 蜂鸣器（有源） | GPIO 直驱或三极管 | 电流较大时用三极管 | 给电即响 |
| 蜂鸣器（无源） | PWM 驱动 | 三极管驱动 | 频率决定音调 |
| 继电器 | GPIO + 三极管/MOS | **必须并续流二极管** | 线圈电流、触点容量 |
| 直流水泵 | GPIO + MOS | 独立供电 + 续流二极管 | 启动电流大于额定电流 |
| 雾化片 | GPIO + MOS | 独立供电 | 不可长时间干烧 |
| 舵机 | 50Hz PWM | 独立 5V 供电，必须共地 | 脉宽 0.5~2.5ms |
| 直流电机 | PWM + H 桥（L298N） | 独立 12V 供电，必须共地 | 转向 + 占空比调速 |

#### 1. 蜂鸣器

```c
#include "driver/gpio.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

#define BUZZER_GPIO   GPIO_NUM_3

void buzzer_init(void)
{
    gpio_set_direction(BUZZER_GPIO, GPIO_MODE_OUTPUT);
}

void buzzer_beep(int times)
{
    for (int i = 0; i < times; i++)
    {
        gpio_set_level(BUZZER_GPIO, 1);
        vTaskDelay(pdMS_TO_TICKS(200));
        gpio_set_level(BUZZER_GPIO, 0);
        vTaskDelay(pdMS_TO_TICKS(200));
    }
}

void app_main(void)
{
    buzzer_init();

    while (1)
    {
        buzzer_beep(3);                               /* 响三声 */
        vTaskDelay(pdMS_TO_TICKS(3000));
    }
}
```

无源蜂鸣器需要用 LEDC 输出音频频率的方波，改变频率即可改变音调。

**调用流程**

| 步骤 | 调用 | 作用 |
| --- | --- | --- |
| 1 初始化 | `gpio_set_direction(引脚, GPIO_MODE_OUTPUT)` | 把引脚配成输出 |
| 2 响一声 | `gpio_set_level(1)` → 延时 → `gpio_set_level(0)` | 有源蜂鸣器：电平直接决定响不响 |
| 3 想变音调 | 改用 LEDC：`ledc_timer_config()` + `ledc_set_duty()` + `ledc_update_duty()` | 无源蜂鸣器：频率决定音调 |

> 有源蜂鸣器内部自带振荡电路，给电平就响；无源蜂鸣器相当于一只小喇叭，必须喂它**方波**才响，改频率才能变调。

#### 2. 舵机

舵机使用 50Hz（周期 20ms）的 PWM，高电平宽度决定角度。**为什么必须 50Hz**：舵机内部按 20ms 为一个周期来解算脉宽，周期不对它就无法正确识别角度，表现是抖动、乱转甚至完全不动。

| 角度 | 高电平宽度 | 占空比（20ms 周期） | 14 位分辨率计数值 |
| --- | --- | --- | --- |
| 0° | 0.5ms | 2.5% | 410 |
| 90° | 1.5ms | 7.5% | 1229 |
| 180° | 2.5ms | 12.5% | 2048 |

```c
#include "driver/gpio.h"
#include "driver/ledc.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

#define SERVO_GPIO   GPIO_NUM_7

/* 注意：ESP32-S3 的 LEDC 最高只支持 14 位分辨率，占空比范围 0 ~ 16383 */
void servo_init(void)
{
    ledc_timer_config_t timer = {
        .speed_mode      = LEDC_LOW_SPEED_MODE,
        .timer_num       = LEDC_TIMER_0,
        .duty_resolution = LEDC_TIMER_14_BIT,
        .freq_hz         = 50,                    /* 舵机固定 50Hz */
        .clk_cfg         = LEDC_AUTO_CLK,
    };
    ledc_timer_config(&timer);

    ledc_channel_config_t ch = {
        .gpio_num   = SERVO_GPIO,
        .speed_mode = LEDC_LOW_SPEED_MODE,
        .channel    = LEDC_CHANNEL_0,
        .timer_sel  = LEDC_TIMER_0,
        .duty       = 0,
    };
    ledc_channel_config(&ch);
}

/* 角度 0 ~ 180 度 对应 脉宽 0.5ms ~ 2.5ms */
void servo_set_angle(int angle)
{
    int duty = 410 + (2048 - 410) * angle / 180;

    ledc_set_duty(LEDC_LOW_SPEED_MODE, LEDC_CHANNEL_0, duty);
    ledc_update_duty(LEDC_LOW_SPEED_MODE, LEDC_CHANNEL_0);
}

void app_main(void)
{
    servo_init();

    while (1)
    {
        servo_set_angle(0);
        vTaskDelay(pdMS_TO_TICKS(1000));
        servo_set_angle(90);
        vTaskDelay(pdMS_TO_TICKS(1000));
        servo_set_angle(180);
        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}
```

**调用流程**：`ledc_timer_config()`（固定 50Hz、14 位）→ `ledc_channel_config()`（把通道绑到引脚）→ 每转一个角度调一次 `ledc_set_duty()` + `ledc_update_duty()`。

> 舵机和 LED 用的是同一套 LEDC，区别只在**频率必须 50Hz**、占空比要按脉宽换算。
#### 3. 驱动电路的三个铁律

1. **限流**：LED 必须串限流电阻，三极管基极必须串限流电阻。**为什么**：LED 导通后内阻极小，直接接 3.3V 会瞬间流过远超它承受能力的电流而烧毁，串一只电阻就能把电流限制在安全范围内。
2. **续流**：继电器、电机、水泵等感性负载两端必须并二极管。
3. **共地 + 独立供电**：大功率负载单独供电，但与主控**必须共地**。

### 7.10 中断

#### 1. 什么是中断

**中断**就是：CPU 正在执行程序时，被外设"叫去"处理一件更紧急的事，处理完再回到原来的地方继续。

打个比方：你在写作业，门铃响了 —— 你会**先在作业本上做个记号**（记住做到哪），去开门，回来接着往下写。中断就是这个过程：**保存现场 → 处理事情 → 恢复现场**。

#### 2. 为什么需要中断（和轮询对比）

| 方式 | 做法 | 问题 |
| --- | --- | --- |
| **轮询** | 主循环不停地问"按键按了吗" | 白白浪费 CPU；问得慢一点就漏掉事件 |
| **中断** | 事件发生时硬件主动通知 CPU | CPU 该干嘛干嘛，事件一个不漏 |

#### 3. 中断的四个步骤

| 步骤 | 发生什么 |
| --- | --- |
| 1 | 外设发生事件（按键按下、串口收到数据、定时器到点） |
| 2 | 硬件产生中断请求，CPU **保存现场**（当前执行到哪、寄存器内容） |
| 3 | 跳去执行**中断服务函数（ISR）** —— 就是我们自己写的那段代码 |
| 4 | ISR 执行完，CPU **恢复现场**，回到刚才被打断的地方继续跑 |

#### 4. ESP-IDF 里怎么写 GPIO 中断

以"按键按下计数"为例，用最简单的做法：**中断里只改一个变量，主循环里再处理**。

```c
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "driver/gpio.h"
#include "esp_attr.h"
#include "esp_log.h"

#define KEY_GPIO   GPIO_NUM_4

static const char *TAG = "key";

/* 中断和主循环都要用它，必须加 volatile */
static volatile int s_key_count = 0;

/* 中断服务函数：只做最简单的事 */
static void IRAM_ATTR key_isr(void *arg)
{
    s_key_count++;                      /* 只加一个计数，别的都不做 */
}

void app_main(void)
{
    gpio_config_t cfg = {
        .pin_bit_mask = 1ULL << KEY_GPIO,
        .mode         = GPIO_MODE_INPUT,
        .pull_up_en   = GPIO_PULLUP_ENABLE,
        .pull_down_en = GPIO_PULLDOWN_DISABLE,
        .intr_type    = GPIO_INTR_NEGEDGE,   /* 下降沿触发（按下时） */
    };
    gpio_config(&cfg);

    gpio_install_isr_service(0);                    /* 第一步：装中断服务 */
    gpio_isr_handler_add(KEY_GPIO, key_isr, NULL);  /* 第二步：把函数挂到引脚上 */

    while (1)
    {
        if (s_key_count > 0)
        {
            ESP_LOGI(TAG, "按下次数 = %d", s_key_count);
            s_key_count = 0;
        }
        vTaskDelay(pdMS_TO_TICKS(100));
    }
}
```

**常用 API 与调用流程**

| 步骤 | 调用 | 作用 |
| --- | --- | --- |
| 1 配引脚 | `gpio_config(&cfg)`，`intr_type` 填触发方式 | 告诉引脚"哪个边沿算一次事件" |
| 2 装服务 | `gpio_install_isr_service(0)` | 全局只装一次，为 GPIO 中断准备好底层服务 |
| 3 挂函数 | `gpio_isr_handler_add(引脚, 函数, 参数)` | 把这个引脚的中断绑到自己写的函数上 |
| 4 等触发 | 硬件自动调用你挂上去的函数 | 不用手写调用，事件来了自动进来 |
| 5 交接 | 函数里只改一个标记，主循环或任务里再处理 | 中断不能久留 |

> 第 2、3 步各做一次，第 4 步是硬件自动发生的，第 5 步是要养成的习惯。忘了第 2 步，中断永远不会触发。
**三个必须注意的点**

1. **`volatile` 不能省** —— 中断里改的变量，编译器优化后可能认为主循环里的值不会变，加了 `volatile` 才会每次都重新去内存里读；
2. **`IRAM_ATTR` 要写上** —— 它把这个函数放进内部 RAM，保证中断能立刻执行；
3. **触发方式要和硬件匹配** —— 按键接 GND 用**下降沿**，接 3.3V 用**上升沿**，抖动厉害的场合可用 `GPIO_INTR_ANYEDGE` 再在软件里消抖。

#### 5. 中断服务函数的三条铁律

- **必须短**：只做"记一笔"，不做耗时的事；
- **不能阻塞**：不能调用 `vTaskDelay()`，也不能在里面等数据；
- **不能打印大段日志**：串口输出很慢，中断里打印很容易拖垮整个系统。

那"必须处理、又花时间"的事怎么办？**中断里丢一个事件出去，交给任务慢慢做** —— 详见 [第 3 册 · 8.4 节「中断配合规范」](03-无线与系统.html#12-中断配合规范)。

#### 6. 中断优先级

- **中断优先级数字越小越优先**，和 FreeRTOS 任务的规则**正好相反**（任务优先级是数字越大越优先）；
- 高优先级中断可以打断正在执行的低优先级中断；
- 一般用默认优先级即可，不需要手动改。

#### 7. 常见坑

| 现象 | 原因 |
| --- | --- |
| 一进中断就重启 | 中断里调用了阻塞接口，或函数没写 `IRAM_ATTR` |
| 一次按下触发好几次 | 按键机械抖动，需要硬件电容或软件消抖 |
| 中断根本不触发 | 忘了 `gpio_install_isr_service()`，或 `intr_type` 填成了 `GPIO_INTR_DISABLE` |
| 中断触发后数据不对 | 共享变量没加 `volatile` |

### 7.11 看门狗

#### 1. 什么是看门狗

**看门狗（Watchdog）是一个倒数计时器**：程序必须每隔一段时间把它"喂"一次（重新装一个较大的数）；如果程序卡死了、没人喂，计数减到 0 时看门狗就**强制重启芯片**。

打个比方：一个必须定时按掉的闹钟 —— 你按时按它就没事，你要是被"卡住"了按不了，它就强制让你"重新开始"。

#### 2. 为什么需要看门狗

嵌入式设备常常**无人值守**（装在机器里、放在野外），程序可能因为电磁干扰、死锁、指针跑飞而卡死。而**卡死比重启更可怕**：卡死的设备永远不会自己恢复，重启至少还能重新工作。

看门狗就是最后一道保险：**宁可重启，也不许永远卡死**。

#### 3. ESP32 里有两类看门狗

| 类型 | 监控谁 | 触发条件 |
| --- | --- | --- |
| **任务看门狗（TWDT）** | 任务 | 某个任务长时间占着 CPU 不让出（通常是忘了 `vTaskDelay`） |
| **中断看门狗（IWDT）** | 中断 | 中断服务函数运行时间过长 |

#### 4. 触发时会看到什么

串口会打印类似这样的日志，然后**芯片自动重启**：

```
Task watchdog got triggered. The following tasks/user did not reset the watchdog in time:
E (5231) task_wdt:  - IDLE (CPU 0)
```

**看到 `Task watchdog got triggered` 就说明是看门狗把芯片重启了**，不是硬件掉电。

#### 5. 什么情况会触发（以及怎么改）

| 原因 | 解决 |
| --- | --- |
| 任务里写了死循环，没有 `vTaskDelay` | 循环里加让出 CPU 的延时 |
| 高优先级任务一直不阻塞 | 让低优先级任务（尤其是空闲任务）有机会跑 |
| 中断服务函数太长 | 中断里只做标记，处理交给任务 |
| 某个操作阻塞时间过长 | 缩短单次阻塞时长，或拆成多次做 |

**关键结论**：绝大多数看门狗触发，都是因为**某个循环里忘了写 `vTaskDelay()`**。

#### 6. 怎么用它

- **默认就是开着的**，正常写程序不用管它，只要记得让出 CPU；
- 配置位置：`idf.py menuconfig` → `Component config` → `ESP System Settings` → `Task Watchdog`；
- 长时间计算前可以手动喂一口：`esp_task_wdt_reset()`；
- **调试时可以临时关掉**（menuconfig 里关闭，或调用 `esp_task_wdt_deinit()`），但**正式产品里绝对不能关** —— 关了之后程序一旦卡死就再也起不来。

**调用流程**：默认就是开着的 → 保证每个循环里都有 `vTaskDelay()` 之类的让出点 → 长时间计算前 `esp_task_wdt_reset()` 喂一口 → 调试期可以临时关，正式产品不能关。

---
#### 7. 别和 eFuse 搞混

- **看门狗**是软件保险机制，随时可以开关，触发后是"重启"；
- **eFuse** 是芯片内部一次性可编程的熔丝（见 6.2 节），写错就报废芯片。

两者名字里都带"保险"的意味，但完全是两回事。
